A Sober Look：语言模型推理进展中的评测陷阱与可复现性

论文：A Sober Look at Progress in Language Model Reasoning: Pitfalls and Paths to Reproducibility
作者：Andreas Hochlehnert、Hardik Bhatnagar、Vishaal Udandarao、Samuel Albanie、Ameya Prabhu、Matthias Bethge
发表：COLM 2025
版本：arXiv:2504.07086v2，2025-10-06；首版发布于 2025-04-09
来源：论文与版本记录、v2 全文
整理与核对：2026-10-20；根据提供的解读整理，并核对原文关键结果。本文没有重新运行模型评测。

1. 论文想回答什么

这是一项评测审计和可复现性研究。作者关注的是：大量数学推理模型报告的提升，有多少能够在控制推理配置、随机性和评测框架后保留下来？

典型研究路线是先将高质量推理轨迹蒸馏到小模型，再用 GRPO 等强化学习方法继续训练，最后报告 AIME、AMC 或 MATH 上的准确率提升。但不同项目可能使用不同的 prompt、temperature、top-p、输出长度、答案提取器和推理后端。

如果方法模型与基线的分数来自不同测量条件，分数差就混合了参数更新和评测配置的影响，不能直接归因于算法。

本文的核心贡献有三项：量化这些影响因素，统一重测公开模型，并提出可复核的评测实践。其结论应限定在调查的模型和配置内；它同时报告了部分方法仍然具有可靠收益的证据。

2. 为什么同一个模型会测出不同分数

2.1 小数据集会放大采样波动

论文在九个模型上分析 AIME'24、AMC'23 和 MATH500 的随机种子影响。同一模型的分数可能出现两位数百分点的变化，而模型权重完全没有改变。

AIME'24 只有 30 道题，单次生成时一道题对应：

130×100%≈3.33 个百分点 \frac{1}{30}\times100\%\approx3.33\text{ 个百分点} 301​×100%≈3.33 个百分点

只要三道题的生成结果变化，整体准确率就可能相差 10 个百分点。

对第 iii 道题，模型在固定评测配置下的单次成功概率记为：

pi(θ)=Pr⁡ξ[fθ(xi;ξ)=yi] p_i(\theta)=\Pr_{\xi}[f_\theta(x_i;\xi)=y_i] pi​(θ)=ξPr​[fθ​(xi​;ξ)=yi​]

其中 ξ\xiξ 表示解码随机性。每道题生成 KKK 次时，平均单次准确率的估计为：

A^(θ)=1NK∑i=1N∑k=1K1[fθ(xi;ξi,k)=yi] \widehat A(\theta)=\frac{1}{NK} \sum_{i=1}^{N}\sum_{k=1}^{K} \mathbf1[f_\theta(x_i;\xi_{i,k})=y_i] A(θ)=NK1​i=1∑N​k=1∑K​1[fθ​(xi​;ξi,k​)=yi​]

这估计的是平均 Pass@1，不能解释为“生成 KKK 次，只要有一次正确就算成功”的 Pass@K。

论文的 bootstrap 实验显示，增加到约 30 次 seed run 后，均值估计明显稳定，因此建议小型 benchmark 至少采用 30 个随机种子。这是其模型和任务上的经验建议，并非所有评测都适用的固定门槛。来源：§3.2 与 Figure 3

需要区分两类不确定性：

  • 解码不确定性：同一道题生成不同输出；增加采样次数可以降低。
  • 题目集合的不确定性：这批题能否代表更广泛任务；重复生成无法增加题目多样性。

即使对 30 道题重复一千次，也仍然只有 30 个不同问题。

2.2 Temperature 和 top-p 改变的是被评测的系统

温度采样分布为：

PT(v)=exp⁡(zv/T)∑uexp⁡(zu/T) P_T(v)=\frac{\exp(z_v/T)}{\sum_u\exp(z_u/T)} PT​(v)=∑u​exp(zu​/T)exp(zv​/T)​

温度趋近于零时，行为趋近 greedy decoding；较高温度允许探索更多输出。top-p 则限制参与采样的候选 token 集合。

提供材料所引用的实验显示，仅改变 temperature 或 top-p 就可能产生数个百分点乃至十余个百分点的变化。这个量级足以影响对部分算法收益的判断，但不能推广成“温度越高，推理越强”。

比较时需要先确定问题：

比较目标 配置原则 结论含义
固定条件下的训练收益 训练前后使用同一配置，并检查多个合理配置 参数更新在这些条件下是否有效
每个模型可达到的表现 在独立验证集上分别调参，给予可比搜索预算 经过同等调优后，哪套系统更强

论文建议针对模型调参，然后跨任务固定配置。作为研究实践，还应明确验证集和搜索预算，防止直接根据测试集最高分挑选配置。

2.3 Prompt、模板和长度上限影响准确率

论文比较了数学提示词加 chat template、只有 chat template，以及原始问题等输入方式。Instruction-tuned 模型对训练时的角色标记和对话边界可能很敏感，移除模板会改变输入分布。

长推理模型还受到最大输出长度限制。模型尚未给出最终答案就被截断，会被评测为错误。但 4K 和 32K token 上限也对应不同的推理预算，不能只比较准确率而忽略成本。

至少应同时报告最大长度、实际生成 token 数和截断比例。相同长度上限也不意味着相同实际计算量。

2.4 固定 seed 不保证跨环境逐 token 复现

提供材料列举了论文中的硬件对照：即使 GPU 型号、Docker 和软件配置相同，不同运行环境仍可能得到不同分数。

可能因素包括浮点计算、kernel、推理后端和执行顺序。自回归生成会放大早期 token 的微小变化，但论文没有完整隔离每一种机制，不能把全部差异简单归因于浮点误差。

实际复现需要记录软件版本、精度、GPU、推理后端和执行配置，不能只提供一个 random seed。

3. 统一重测后，哪些收益仍然存在

作者使用 LightEval 0.8.1 和 vLLM，在 A100 上评测六个 benchmark：AIME'24、AIME'25、AMC'23、MATH500、Minerva 和 OlympiadBench。

AIME/AMC 使用 10 个随机种子，其余使用 3 个。作者承认这低于前面建议的 30 次，是计算成本与精度之间的折中。来源：§4.2

提供解读引用的 Figure 1 数字如下，单位为准确率百分比：

Open-RS3 在 AIME'24 上只比基线高 1 个百分点，论文的检验未支持显著提升。但 DeepScaleR 在 AIME'25、MATH500 和 OlympiadBench 上仍有显著收益；v2 中的 Nemotron-RR 也显示了较稳健的改善。来源：Table 3

因此，应逐个方法、逐个任务判断，不能用“部分收益未复现”替代对全部 RL 方法的结论。

3.2 作者怎样做配对统计检验

先计算每个模型在每道题上的平均正确率：

p^m,i=1K∑k=1Kcm,i,k \widehat p_{m,i}=\frac1K\sum_{k=1}^{K}c_{m,i,k} p​m,i​=K1​k=1∑K​cm,i,k​

再对同一道题计算模型与基线的差值：

di=p^RL,i−p^base,i d_i=\widehat p_{\mathrm{RL},i}-\widehat p_{\mathrm{base},i} di​=p​RL,i​−p​base,i​

作者对这些差值进行单侧 paired t-test 和 Wilcoxon signed-rank test。这利用了相同题目上的配对结构，比仅比较两个总分更有信息。

仍需注意：

  • 标准差区间重叠，不能替代显著性检验；不重叠也不是完整的分析。
  • 未达显著，不能直接证明效果为零；证明等效需要事先定义有意义的差异范围。
  • 小题目集和大量比较仍需要审慎处理；较小的 p 值阈值并不自动完成多重比较校正。

3.3 Base Model 与蒸馏模型上的 RL 收益不同

从已蒸馏的 R1-Distill 继续 RL，与从 Qwen Math Base 开始 RL，起点不同。

例如，提供解读引用 Table 3 中 Qwen2.5-Math-7B 的 MATH500 准确率为 64.3%，Oat-Zero 为 79.4%，提高 15.1 个百分点；对应的 Math Instruct 模型达到 82.9%。这说明 RL 可以明显改善 Base Model，但“优于原始 Base”与“优于成熟后训练基线”是不同研究主张。

对 SFT 和 RL 的跨项目比较也需要保留限定：训练数据、质量、预算和起点未全部对齐，不能据此证明同等条件下 SFT 必然优于 RL。

4. 三个推理现象应怎样解读

4.1 错误回答常常更长，但长度未必导致错误

作者观察到错误答案通常对应更长的推理轨迹，即使排除截断后仍有类似趋势。

困难题目可能同时导致长输出和低正确率，因此这是相关性证据。要证明“缩短推理会提高正确率”，需要主动控制推理预算或进行其他干预。

4.2 Pass@1 提升可以伴随 Pass@k 优势减少

对固定题目、独立同分布采样、单次成功率为 pip_ipi​ 的情况：

Pass@⁡k(xi)=1−(1−pi)k \operatorname{Pass@}k(x_i)=1-(1-p_i)^k Pass@k(xi​)=1−(1−pi​)k

跨题目平均应写为：

Pass@⁡k=1N∑i[1−(1−pi)k] \operatorname{Pass@}k=\frac1N\sum_i[1-(1-p_i)^k] Pass@k=N1​i∑​[1−(1−pi​)k]

一般不能将所有题目的平均成功率直接代入单题公式。

部分 RL 模型的单次正确率提高，但大 kkk 时对基线的优势消失或反转，与成功概率向少数模式集中的解释一致。不过 Pass@k 只能提供间接证据；要讨论 diversity collapse，仍应分析轨迹差异、答案分布等指标。

4.3 无关 prompt 也可能改变表现

作者复查了给 Qwen2.5-Math 加入 Lorem Ipsum 占位文本的现象。个别无关提示词能得到较高分数，表明输入扰动会影响行为；这不说明任意无关文本都有益，也不揭示其完整机制。

5. 对具身 Agent 评测的启发

具身任务中，成功率还依赖初始状态、物体布局、仿真环境、控制频率、动作预算、超时和 reset 逻辑。可以将同类审计分为三步：

  1. 协议检查：比较任务版本、success checker、控制接口和执行预算。
  2. 受控复测：让模型面对相同 initial states，记录配对 episode 结果。
  3. 泛化检查：改变布局、初始状态和扰动类型，检查收益是否保留。

对长时序任务，还应报告 recovery rate、动作数、失败类型、碰撞次数和人工干预成本。若排名变化，需要通过单因素干预解释其来源。

这些是方法论迁移，论文没有完成对应的机器人实验。

6. 阅读时应保留的判断边界

这篇工作的价值在于建立了一条可复核的证据链：发现协议差异，量化影响，再统一实验并修正结论。

评测系统本身需要被研究；统计显著性、实际效果大小与跨分布泛化也需要分别报告。统一框架提高了可比较性，但仍需要检查 parser 和预算是否适合被测模型。

还应注意，作者允许模型使用各自的解码参数，并按模型类型选择长度限制。统一流程不等于所有模型拥有完全相同的配置或成本；将结果解释为固定配置下的训练因果效应时，需要进一步检查每一组训练前后对照。
