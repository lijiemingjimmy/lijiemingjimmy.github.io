ENPIRE：让机器人自己做策略改进

ENPIRE（Agentic Robot Policy Self-Improvement in the Real World）的核心思路，是把真实机器人实验组织成一个可以反复运行的闭环：重置环境，执行策略，判断结果，根据失败继续改进。

它关注的不是让 Agent 一次性写出完美控制器，而是把机器人研究中原本由人完成的试验、观察、调参和改代码，逐步交给 Agent 完成。

据我的观察呢，他们会强调一种独特风格的“zero-shot”。比如机械臂发现这只手完成不了这个工作 但是他在代码库中发现了handoff_skill.md然后他就会左手拿的东西给到右手。这是个很好的思路啊。然后他做完之后会继续修改甚至增加新的skill。

1. 真实世界缺少一个可靠的实验循环

在仿真里，环境可以随时 reset，奖励可以直接读取，试错的成本也很低。Agent 可以不断修改代码、运行实验，再根据分数继续搜索。

真实机器人则不同。物体可能停在任意位置，摄像头会被遮挡，动作可能损坏设备，实验结束后还需要把场景恢复到可以再次尝试的状态。很多机器人项目实际上是由人充当传感器和执行器：人观察结果，再把问题描述给 Agent。

ENPIRE 的重点，是先把这些人工步骤整理成机器可以调用的接口。只要重置和结果判断足够可靠，真实机器人也可以拥有类似自动研究的反馈循环。

2. ENPIRE 的四个模块

模块 作用 需要解决的问题
Environment 重置场景并检查初始状态 物体放回哪里、机器人是否安全、初态是否有效
Policy Improvement 修改或训练策略 如何根据失败现象提出下一次改动
Rollout 执行策略并记录过程 如何统一运行、保存轨迹和区分失败原因
Evolution 分析日志并推动下一轮实验 是否值得保留当前改动、下一步应搜索什么

这四个模块的关系可以理解为：

Environment 提供可信的实验条件 → Rollout 产生真实反馈 → Evolution 分析问题 → Policy Improvement 修改策略。

它们不一定对应四个独立的软件包，更像是一种组织机器人研究的方式。已有的控制器、运动规划器和训练代码，都可以放进这个循环中。

3. 重置往往比训练更难

仿真中的 reset 可能只是调用一个函数，真实世界的 reset 则是一套动作流程。

例如 Push-T 任务中，机器人需要找到桌面上任意位置的 T 形物体，将它重新放回初始位置；插针任务需要重新找到小物体和插孔；双臂任务还要考虑可达范围、遮挡和碰撞。

因此，一个可用的重置模块至少需要回答：

  • 物体是否真的回到了有效初始状态？
  • 机器人、夹爪和传感器是否处于可以运行的状态？
  • 当前初态是否超出了策略训练时的范围？
  • 重置失败时，系统能否停止并保留这次失败？

重置范围本身也是任务能力的一部分。如果只能处理很窄的物体位置或姿态，就应该把这个范围写进实验条件，而不是把它称为通用能力。

4. 奖励函数和成功判断决定了搜索方向

Agent 能不能改进，很大程度上取决于它收到的反馈是否正确。

对于插入、放置和高度变化等任务，几何关系、深度、力传感器或物体高度可能已经足够。对于扎带等柔性物体，单一相机位置很难判断是否真的穿过，需要结合多个视角、分割结果、深度和成功/失败示例。

奖励函数可以由 Agent 通过代码搜索得到，但需要注意两件事：

  1. 奖励高不一定代表真实任务成功。策略可能只学会利用奖励函数中的漏洞。
  2. 奖励判断需要足够快，否则大量时间会花在评估本身，而不是策略改进上。

因此，奖励函数最好同时具备可解释性和可检查性。对于复杂任务，可以先收集少量成功与失败样例，让 Agent 生成一个可运行的判定函数，再用留出的样例检查它是否真的理解了成功条件。

5. 策略改进更像是有反馈的搜索

ENPIRE 并不要求 Agent 发现全新的强化学习算法。很多有效改动可能只是对控制器、数据、模型规模或超参数进行逐步搜索。

一个典型循环是：

  1. 先运行基线策略，记录成功率和失败现象。
  2. 让 Agent 根据轨迹和日志提出一个具体假设。
  3. 修改策略、训练代码或奖励函数。
  4. 在相同条件下重新运行。
  5. 比较结果，保留有效改动，回退无效改动。

例如在插针任务中，Agent 可能发现当末端执行器接近孔的高度后，应该减少 XY 方向动作、增加 Z 方向动作。这种改动未必是新的算法，但它可以解决当前任务中的具体失败模式。

这类搜索的价值在于，很多局部技巧人能够理解，却不值得人逐条手写和测试。Agent 可以快速尝试更多组合，再由实验结果筛选。

6. 适合 ENPIRE 的任务

一个任务越容易重置、越容易判断成功，就越适合放进这个闭环。

比较适合的任务通常具有以下特点：

  • 可以自动恢复到多个有效初始状态；
  • 成功与失败能够通过图像、深度、力或几何关系判断；
  • 单次实验时间和设备消耗可控；
  • 失败不会让机器人或场景进入无法恢复的状态。

长时序任务、柔性物体、需要很多中间状态的任务，以及化学实验一类不可逆过程，会让重置和奖励判断变得困难。这并不意味着它们不能使用 ENPIRE，而是需要先解决实验环境本身，再谈策略搜索。

7. 多机器人和多 Agent 可以提高反馈速度

单个 Agent 可能无法稳定解决任务，但多个 Agent 在多台机器人上并行尝试，可以增加每轮 rollout 的数量，让有效经验更快出现。

一种简单的组织方式，是让不同工位使用各自的 Agent 和日志，同时共享代码仓库、实验结果和失败分析。这样每个 Agent 可以独立尝试，也可以吸收其他工位找到的改动。

并行规模越大，实验吞吐量越高，但 Token、设备和维护成本也会增加。八台机器人、几十个 Agent 是 ENPIRE 论文中的实验条件，不是所有任务都需要的配置。真正重要的是每次实验都能被记录、比较和复现。

8. 人在循环中的位置会发生变化

当 Agent 能够观察视频、读取代码、分析日志并直接修改策略后，人的工作就不再只是手动调参。

人的价值更多体现在：

  • 选择值得解决的任务和目标；
  • 规定速度、精度和安全要求；
  • 判断实验结果是否具有实际意义；
  • 在系统无法可靠恢复时介入；
  • 为 Agent 否决明显不合理的方案。

因此，ENPIRE 更像是把机器人研究从“人手动推动每一次实验”，转向“人设定目标，Agent 执行大量可验证的实验”。

9. 对机器人研究的启发

ENPIRE 最重要的启发，不是某一种特定模型或控制算法，而是把真实机器人也当作一个可以提供反馈的研究环境。

后续可以沿着几个方向扩展：

  • 将仿真、域随机化和真实机器人实验接入同一循环；
  • 让更强的视觉模型直接从视频示范中提取操作过程；
  • 让 Agent 自动生成和改进奖励函数；
  • 用更大的机器人集群提高实验吞吐量；
  • 让高层 Agent 负责研究和规划，低层控制器负责实时、稳定的动作执行。

但无论模型多强，实验循环仍然需要可信的重置、清楚的成功标准和可比较的记录。没有这些基础，Agent 只是在更快地重复不可靠的实验。
