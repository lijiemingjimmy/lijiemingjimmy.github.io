Gemini Robotics 2.5：把动作能力、任务闭环和机器人学习放在一起看

Google DeepMind，2026 年 11 月 10 日发布。

这次发布可以围绕一个问题来理解：一个已经会操作的机器人，怎样更快地学会更多任务，并在真实环境里把任务稳定做完？

回答这个问题，需要同时看三件事。动作模型要处理抓取、接触和工具使用；高层模型要知道任务做到哪一步、哪里需要重试；研发系统还要持续提供有用的数据和改进方法。Gemini Robotics 2.5 的看点就在这三个层次之间的配合。

目前公开材料以能力展示和系统工作流为主。下面会把官方结果、帮助理解的公式，以及我认为值得做的研究分开讲。

1. 先把三个模型的分工讲清楚

角色 主要处理什么 例子
Gemini Robotics ER，具身推理模型 理解任务、跟踪流程、决定下一步 判断哪个托盘位置还没放零件
Gemini Robotics 2.5，VLA 动作模型 根据观测和任务生成动作 将手伸入料箱，抓取支架并放入托盘
Gemini 4 Argon，通用推理与工具使用模型 帮助搭建仿真、标注数据、分析失败、改进控制程序 重建料箱场景，生成练习轨迹，检查失败原因

官方工业案例明确说明：ER 跟踪工作流，Robotics 2.5 控制手和机械臂。发布页在这里使用的是 Gemini Robotics ER 的系列名称；ER 2 还出现在安全评测的基线中，不能仅凭这一点确定所有演示的具体部署版本。官方介绍

可以用一个概念图理解这些角色：

用户任务 + 当前场景
        ↓
ER：判断当前阶段，选择下一步目标
        ↓
Robotics 2.5：生成机器人动作
        ↓
机器人执行 → 新观测 → ER / 动作模型继续调整

执行记录、示范、任务需求
        ↓
Argon：建仿真、分析失败、标注和改进程序
        ↓
新数据 / 新技能代码 / 新训练方案
        ↓
验证后用于机器人系统

这个图是功能分工，不是 Google 公布的精确网络结构。Argon 也能直接调用机器人工具，但它在机器人研发中的作用，和 VLA 每次生成动作的作用需要分别讨论。

高层目标与低层动作怎样衔接？

假设任务是“把物料箱中的支架按顺序放进托盘”。高层需要决定当前操作对象、目标位置、是否完成和是否重试。为了说明接口，可以写成：

gt=fER(o≤t,ℓ,mt),At=πθ(ot,qt,gt). g_t=f_{\mathrm{ER}}(o_{\le t},\ell,m_t), \qquad A_t=\pi_\theta(o_t,q_t,g_t). gt​=fER​(o≤t​,ℓ,mt​),At​=πθ​(ot​,qt​,gt​).

这里，ooo 是观测，ℓ\ellℓ 是总任务，mtm_tmt​ 是任务进度记录，qtq_tqt​ 是机器人本体状态，gtg_tgt​ 是当前目标，AtA_tAt​ 是接下来执行的一段动作。

这只是常见分层控制的抽象。官方发布文章没有完整披露 Robotics 2.5 的动作表示、action chunk 长度、控制频率和模型内部接口，不能从这两个公式反推其具体实现。

直观地说，高层发现“这个格子还空着”，动作模型才需要解决“怎样把零件拿稳并放进去”。任务状态判断错了，再精确的动作也可能做错事情；目标判断正确，接触控制失败也无法完成任务。

2. 灵巧性到底体现在哪里？

官方评测覆盖超过 200 种任务，并报告相对此前基线，按任务类别不同，成功率提高约 30%–100%，完成速度提高约 20%–30%。这些是发布页的汇总表述，不能理解为所有任务统一增加了 30–100 个百分点，也不能据此得出所有任务都接近满分。官方评测说明

更有用的是看具体任务。下面整理你提供材料中涉及的任务，并与官方图表说明核对：

任务 Robotics 2 Robotics 2.5 需要处理的关键问题
关闭黑色工具箱盖 0% 93% 对齐、接触、盖体运动和闭合状态
从挂钩上取下杯子并放到桌上 29% 75% 先解除挂接，再移动物体
用刷子把垃圾扫进簸箕 0% 52% 工具姿态、持续接触和多次调整
装箱电饭煲 0% 40% 大物体姿态、空间约束和多步配合
用夹子装糕点 5% 100% 通过工具建立稳定接触
解开丝带蝴蝶结 0% 70% 可变形物体、拉动次序和状态变化
悬挂开衫 0% 62% 衣物形变、双臂配合和挂接关系
折叠裤子 0% 40% 布料形状、抓取点和折叠进度

来源：官方任务对比图。百分比对应各自的测试设置；公开博客不足以完整重建所有任务的样本量和统计误差。

这些任务让人看到两种变化。一是模型能处理更多复杂接触过程；二是能力仍然很不均匀。夹糕点达到 100%，不代表折叠、装箱和扫垃圾也具有同样可靠性。

为什么 contact-rich 比“到达一个位置”更难？

以关工具箱为例，机器人先要让手接触正确部位，再推动盖子沿约束方向运动。盖子可能被内部物体挡住，接触点可能滑动，接近闭合时还可能需要改变施力方向。几何位置正确只是其中一个条件。

这里的控制过程更接近：

接近 → 建立接触 → 判断物体是否移动 → 调整姿态或施力 → 确认结果

工具使用又增加了一层关系：用夹子夹糕点时，手控制夹子，夹子才接触糕点。策略必须处理手—工具—物体之间的运动传递。

对于衣物和丝带，同一个物体的形状会随动作改变。识别出“这是蝴蝶结”还不够，机器人需要判断哪一端可以拉、另一端是否需要固定，以及拉动后是否真的松开。这些例子解释了任务为什么难，但官方展示本身还不能说明模型内部采用了哪一种接触状态表示。

3. 多种机器人形态，说明了什么？

官方展示包括使用五指、22 自由度 SharpaWave 手的 Apollo 2，以及使用双指平行夹爪的 Franka Duo。硬件说明

二者可以共享“拿起物体”“放到容器中”这样的任务语义，但动作空间差异很大。五指手需要协调更多接触点，夹爪的抓取方式则更受开合方向约束。

因此，跨形态的通用性至少包含三个问题：

  1. 任务知识能否共享，例如理解哪个物体应该放到哪里。
  2. 控制是否需要针对硬件适配，例如关节映射、动作尺度和控制器。
  3. 未见过的硬件需要多少新数据，才能达到可用性能。

这次展示支持模型在多种平台上工作的能力。公开结果还不足以回答第三个问题，也不宜直接写成“任意新机器人零样本接入”。

4. 奔驰工厂的 96%，应该怎样理解？

工业试点位于德国 Sindelfingen 和匈牙利 Kecskemét 的奔驰生产线，使用 Apptronik Apollo 2。任务是 automotive kitting：从散装料箱中取出金属零件，按生产需要放入有序容器。官方报告成功率为 96%，并引用合作方对数周后训练改善效果的描述。工业试点说明

这个任务有实际价值。生产准备要求物体选对、放置顺序正确、缺失能被发现。ER 的流程跟踪和 VLA 的动作控制在这里同时发挥作用。

不过，评估长期自治，还需要知道这个 96% 的统计单位：一次抓放、一个完整托盘，还是一次任务？是否允许重试？有多少人工介入？连续运行多久？公开博客没有充分交代这些信息，所以这应被记录为特定工业概念验证的结果。

一个简单例子能说明统计单位为什么重要。假设某流程包含 20 个独立子步骤，每步成功率都是 96%，且任何一步失败都会终止任务，那么：

P(全程成功)=0.9620≈44.2%. P(\text{全程成功})=0.96^{20}\approx44.2\%. P(全程成功)=0.9620≈44.2%.

这是说明性计算，与奔驰试点的实际统计定义无关。真实步骤之间往往相关，而且系统可能具备重试和恢复能力。

对机器人研究更有用的指标组合是：完整任务成功率、每小时人工介入次数、恢复耗时、连续自治时长，以及物体损坏或流程错误次数。它们能区分“偶尔做得很好”和“可以持续承担工作”。

5. Argon 怎样帮助机器人学习？

Robotics 2.5 发布页将 Argon 列为研发加速的重要因素。更具体的工作流来自 2026 年 10 月 13 日的 Argon for Robotics 技术博客。下面几项属于该博客的独立案例，不能合并成 Robotics 2.5 的完整训练配方。

5.1 Real2Sim：把真实经验变成可以练习的环境

从一段真实机器人操作记录出发，Argon 帮助构建 MuJoCo 场景，并调整物体和场景配置。输入可以包含多视角图像、关节状态和触觉力记录。

这里有两个不同目标：画面要对得上，接触过程也要对得上。一个杯子渲染得很像，但质量、摩擦或碰撞形状不对，机器人在仿真中学到的动作仍可能无法迁移。

可以把校准思路概括为：

min⁡ϕ  λILvisual(ϕ)+λFLcontact(ϕ), \min_\phi\;\lambda_I L_{\mathrm{visual}}(\phi) +\lambda_F L_{\mathrm{contact}}(\phi), ϕmin​λI​Lvisual​(ϕ)+λF​Lcontact​(ϕ),

ϕ\phiϕ 代表几何、物理参数和场景设置。这个公式用于解释两个目标，并不是官方公布的可微优化算法；实际展示包含 Agent 观察结果、修改代码和配置、重新运行的迭代过程。

官方示例要求物体运动由 MuJoCo 接触动力学产生，不能在运行中直接修改物体位姿来制造成功。这个约束很关键：如果只追求画面一致，程序可以把物体移到正确位置，但这样的轨迹无法教机器人建立真实接触。Real2Sim 示例

我的理解是，这里需要分清三种东西：

系统 主要生成什么 误差从哪里来
视频世界模型 未来图像或视觉 latent 学习到的视觉动态预测不准确
MuJoCo 等物理仿真器 指定模型和参数下的运动、接触 建模、参数与数值近似不准确
构建仿真的 Agent 场景代码、物理配置和测试程序 误识别场景、设置错误、验证不充分

Argon 在这个案例中主要承担第三种角色，MuJoCo 承担物理计算。博客还展示了控制视频世界模型的其他案例，需要分别评价。

5.2 合成数据：模型生成的练习是否真的有用？

附件对应的 Argon 实验报告：围绕 77 个单臂与双臂课程任务生成 4,500 多条仿真轨迹；加入合成经验后，真实任务成功率从 56% 提高到 75%，完成时间从 35 秒降到 24 秒。Argon 数据生成案例

56% 到 75% 是提高 19 个百分点。它支持“这组自动构建的练习对真实机器人有帮助”，但不能解释成 Robotics 2.5 相对 Robotics 2 的直接消融结果。

可以把工作流写为：

少量真实场景信息
    → Agent 构建和校准仿真
    → 设计任务变化与控制程序
    → 运行并检查合成轨迹
    → 与真实数据结合训练 VLA
    → 回到真机检查收益

研究上最重要的是最后一步。合成数据量越大，越需要知道它增加了哪些有用变化。重复生成同一种容易成功的场景，未必能帮助策略处理真实世界中少见但关键的失败。

例如插入任务，如果仿真中物体总是精确对齐，合成十万条成功轨迹也可能没有教会机器人处理轻微卡滞。更值得生成的是不同初始偏移、接触角度和摩擦条件下，能够通过调整完成的轨迹。

5.3 Hindsight labeling：看完全过程，再判断每段动作在做什么

Argon 的另一个案例是为 136 秒的 ALOHA 2 折纸视频做分层标注：整体目标、6 个语义子任务、17 个原子操作，以及进度和质量信息。材料还涉及识别停顿、抓取不稳定和重复尝试。标注案例

Hindsight 的作用是利用后续结果重新理解前面的动作。某次拉动看起来没有明显变化，但后面纸张成功展开，可能说明它是在释放一个折痕；另一次动作看起来很活跃，但任务没有前进，可能只是无效重试。

这可以启发一种训练设计：

L=E(ot,at)∼D[wt ℓ(πθ(ot),at)]. L=\mathbb E_{(o_t,a_t)\sim D} \left[w_t\,\ell(\pi_\theta(o_t),a_t)\right]. L=E(ot​,at​)∼D​[wt​ℓ(πθ​(ot​),at​)].

其中 wtw_twt​ 表示片段对当前训练目标的价值。它是帮助理解加权学习的公式，不能据此断言 Robotics 2.5 已经采用这一精确损失。

这里有一个值得特别研究的问题：无效动作和恢复动作不能简单混在一起降权。

抓空的动作可能不适合作为理想抓取监督，但抓空后的重新观察、调整姿态和成功重抓，是恢复策略需要的数据。可以将记录区分为正常推进、失败事件和有效恢复，再让不同训练目标使用这些片段。

还有一个容易混淆的点：模型给出的“任务进度分数”不自动等于强化学习中的 value function。严格的 value 取决于未来奖励、策略和时间范围；一个视频进度估计器还需要校准，才能可靠承担价值学习或奖励生成的角色。这是对工作流的研究判断。

5.4 改程序，也是一种改进机器人能力的方法

SO-101 案例中的三次执行时间为 58.9、22.9 和 17.4 秒。Agent 观察执行记录，修改控制程序、速度或放置方式，再运行验证。程序改进案例

这说明改进可以发生在不同位置：

θ→θ′更新策略权重,H→H′更新程序、工具与执行逻辑. \theta\rightarrow\theta'\quad\text{更新策略权重}, \qquad \mathcal H\rightarrow\mathcal H'\quad\text{更新程序、工具与执行逻辑}. θ→θ′更新策略权重,H→H′更新程序、工具与执行逻辑.

两者也可以结合：先用程序化探索找到可行操作，再把经过验证的轨迹用于训练动作模型。

不过，三次迭代的演示还不足以建立稳定的学习曲线。进一步评测需要随机化场景，固定每轮试验预算，检查速度提升是否损害成功率，并测试改好的程序能否用于新位置和新物体。

6. 安全性有两个不同层次

第一个层次是执行时的物理安全。官方称 inference-time reasoning guidance 改善了障碍物附近和人员附近的安全任务完成表现，提升分别为 33% 和 43%。这两个数是提升幅度，不能写成绝对成功率。博客没有完整披露其控制机制，因此不能直接判断它采用 CBF、MPC 或某种独立 critic。安全引导说明

第二个层次是 Agent 对危险请求的处理。ASIMOV-Jailbreak 测试诱导模型接受不安全任务的攻击。官方报告 Argon 的 jailbreak resistance 为 99.5%，ER 2 基线为 82%。这是提示攻击评测，不能解释成真实机器人碰撞概率只有 0.5%。Agent 安全评测

二者分别检查“是否接受危险任务”和“执行过程中是否避开危险”。一个模型可以正确拒绝危险指令，也可能在执行正常任务时因为定位或接触误差造成问题。评价实际系统时，两类错误都需要统计。

7. 公开结果还不能回答的几个问题

性能提升主要来自哪里？ 参数、架构、真实数据、合成数据、后训练和推理时引导可能共同变化。缺少控制变量的消融，就无法给每项因素分配贡献。

200 多种任务中，哪些是未见任务？ 任务覆盖广度和泛化能力有关，但不是同一个统计量。需要区分新物体、新布局、新任务组合、新物理条件和新硬件。

仿真校准在新动作下是否仍然成立？ 根据一条演示调好参数，可能只解释了这条轨迹。真正有用的数字孪生应当对没有参与校准的动作也给出可信预测。

任务进度与失败判断是否可靠？ 如果高层误判“已抓稳”或“已经放好”，会把错误带到后续阶段。应当单独测试这些判断，而不是仅在任务失败后笼统归因于动作模型。

普通研究者能复现哪些部分？ 发布页说明 Robotics 2.5 正面向机器人合作伙伴推出。本次博客没有提供足以完整复现训练的权重、数据配方和独立消融。可以复用其系统思路，但不能把思路重实现当成原模型复现。发布范围

8. 对 Robot-Use Agent 和灵巧操作研究的启发

下面是我基于材料提出的实验方向，不是 Google 已验证的结论。

方向一：把执行、程序改进和参数学习分开评测

配置 允许改变什么 主要测什么
固定 VLA 当前观测，模型权重固定 基础动作能力
VLA + 高层 Agent 子任务、重试和恢复选择 在线决策的价值
Agent + 可修改技能程序 跨试次修改程序 程序层面的经验积累
Agent + 合成数据后训练 场景、数据和策略权重 学习流程的改进能力

四种配置需要记录各自的真实尝试次数、模型调用、训练计算量和人类投入。在来源任务上允许学习，随后冻结改进产物，在新测试实例上评估，才能判断收益是否能迁移。

方向二：研究 Agent 能修复哪些动作失败

可以将错误按实际原因拆开：目标选错、姿态不对、接触滑脱、物体卡住、阶段判断错误。先检查高层重观察或调用恢复技能能解决多少，再决定哪些错误需要新增示范或更新动作模型。

这样能回答一个具体问题：一个固定 VLA 的可用能力，能被更好的执行组织释放出多少？对于灵巧操作，还可以比较视觉反馈与视觉加触觉反馈，检查失败判断是否更及时、更准确。

方向三：评估 Agent 构建的仿真是否可用于学习

训练仿真和评估仿真应该分开。Agent 可以修改自己的练习环境，但不能修改最终评估环境的物理参数或成功标准。

同时检查三件事：真实轨迹能否重放，未参与校准的动作能否预测，以及用合成数据训练后的策略是否改善真机表现。只满足第一项，可能只是拟合演示；第三项才直接对应机器人学习价值。

这个方向与 CEL 可以形成互补：CEL 利用群体真实经验选择更有用的训练片段，Argon 式工作流则尝试把真实经验扩展为新的练习环境和合成经验。二者共同面对的问题是：怎样从一次执行中提取可以迁移的知识，而不只是重复同一场景。

相关笔记：Metatron、On Agentic Manipulation Policies、Recova。

9. 我会怎样定位这次工作

Robotics 2.5 展示了较强的复杂操作能力，也展示了由高层推理配合动作模型完成实际工作流的价值。Argon 部分则把问题进一步推进到：模型能否帮助研究者构建环境、理解经验，并改善下一轮训练和执行。

对研究选题而言，我更关心这条可验证的闭环：

执行任务 → 找到具体失败 → 选择程序修复或数据补充 → 在独立实例上验证 → 保存确实有用的改进。

把每一步的输入、权限、预算和输出记录清楚，才能判断系统是在积累可复用的操作能力，还是只为当前演示投入了更多调试时间。
