Metatron：让 Agent 写运动目标，让控制器协调全身

让人形机器人跨过一个障碍物，可以为跨栏重新训练策略，也可以准备一段完整跳跃动作让它跟踪。Metatron 提供了另一个接口：高层代码指定身体部分的目标位置、朝向和到达时间，冻结的控制器根据当前状态补全全身运动。

这使 Coding Agent 有了一个比较具体的工作对象。它可以修改起跳时机、落脚位置、阶段切换和恢复条件，然后在仿真中测试；机器人关节之间怎样配合，交给已经训练好的运动控制器。

项目：Metatron: A Promptable Whole-Body Execution Layer for Humanoids，NVIDIA 与 Dollhouse Robotics，作者包括 Chen Tessler、Yifeng Jiang、Alec Otto、Yi Shi、Umar Iqbal、Gal Chechik、Xue Bin Peng。官方主页｜论文 PDF｜交互 Demo

本笔记以提供的解读为基础，核对了官方项目页、ProtoMotions 仓库及相关工作。论文 PDF 与模型卡本次未成功读取，因此细粒度配置和两组二手实验数字单独标出核查状态。研究建议与项目已展示的能力分开讨论。

1. 它改变的是机器人技能的调用方式

一个任务专用策略，通常把任务要求写进训练奖励。换一个任务，可能需要修改奖励、重新训练或微调。

运动跟踪策略则把任务要求放进 reference motion。底层可以复用，但高层要提供较完整的运动目标，解决参考动作从哪里来、怎样对齐场景等问题。

Metatron 允许高层只给出部分要求。例如：“一段时间后，右脚到这里；躯干朝前；其余身体动作自行协调。”它仍然能够接收较密集的参考，因此稀疏目标与运动跟踪可以在同一套目标接口中切换。

用一个概念式表示：

at=πθ(ot,gt,mt), a_t=\pi_\theta(o_t,g_t,m_t), at​=πθ​(ot​,gt​,mt​),

其中 oto_tot​ 是当前可用状态，gtg_tgt​ 是运动目标，mtm_tmt​ 表示哪些目标有效，ata_tat​ 是底层动作。这是接口抽象，不是论文网络定义的逐项复写。

Mask 表示哪些维度交由外部约束，不表示把其余关节冻结。 未指定的身体部分可以参与平衡和运动协调。

也要区分“目标”与“保证满足的硬约束”。给定的位置可能超出可达范围，到达时间也可能不符合动力学要求。学习到的控制器会尝试响应，接口本身不提供任意目标都可实现的保证。

2. Prompt 是结构化运动信息

Metatron 的运行接口使用位置、朝向、速度、到达时间以及目标掩码。这里的 prompt 与给聊天模型发送一句自然语言不是同一层接口。官方接口说明

输入要素 高层需要表达什么 例子
身体部位 哪个部位需要满足要求 右手、左脚、躯干
位置和朝向 运动的空间目标 右手伸向前方，躯干转向目标方向
坐标系 目标相对于哪里定义 世界坐标、身体局部坐标
时间 何时希望达到目标 未来若干时刻的脚部落点
Mask 哪些量参与约束 指定脚位置，让双臂自由协调
速度和朝向目标 怎样移动与面向哪里 向前行走，同时改变身体朝向

坐标系和时间并非无关紧要的细节。相同的“向前 40 cm”，相对当前身体和相对世界坐标会产生不同目标；每次循环都把到达时间重置为同一个未来间隔，也可能导致目标不断被推迟。

这意味着一个好用的技能接口，既要提供足够少的参数，也要把单位、参考系、有效期限和状态切换说清楚。否则，Agent 写出的代码语法正确，运动含义仍可能错位。

3. Coding Agent 和实时控制各自负责什么

整个系统有两个时间尺度：

开发阶段，Agent 根据任务与反馈改代码。运行阶段，普通技能程序读取当前状态，生成目标，控制器持续响应。LLM 不需要在每个控制周期内重新推理。

官方页面明确说明，真机步态改进使用 Claude Code 辅助拟合脚部轨迹规则；多个仿真新技能由 GPT-6 Astra 在人类指导下修改目标生成代码、时间安排和运动参考，是否部署由人决定。Agent-assisted skill development

因此，Agent 的主要搜索空间是：

  • 如何把任务拆成运动阶段。
  • 每个阶段约束哪些身体部位。
  • 目标随时间和状态怎样变化。
  • 什么情况下进入下一阶段或恢复模式。

控制器承担的是这些目标下的身体协调。Agent 不必自己解出每个关节的动作，但仍需要判断目标是否合理，以及底层策略是否具备相应能力。

4. 训练主线：完整运动教师 → 稀疏目标学生

官方项目页把学习分成两步：先通过强化学习训练完整运动跟踪器，再以冻结跟踪器监督带掩码目标的生成式策略。之后冻结策略，通过代码开发技能。训练流程

4.1 教师先学会执行完整参考

完整参考包含较密集的身体位置、朝向和时序信息。教师根据当前状态与参考动作产生控制输出，可抽象为：

atT=πT(st,Gtfull). a_t^T=\pi_T(s_t,G_t^{\mathrm{full}}). atT​=πT​(st​,Gtfull​).

参考描述希望身体怎样运动，但机器人还要学会支撑、转移重心、协调关节和应对物理接触。强化学习承担这部分从运动目标到可执行动作的转换。

所给材料列出 BONES、AMASS/LAFAN、恢复动作与 SAMP 场景交互等数据来源。这些具体数据组合本次未从模型卡重新核实，不据此推断每一种发布模型都具有相同训练覆盖。

4.2 学生学习“缺少部分参考时怎样行动”

训练时对目标进行遮盖，得到 G~t\tilde G_tG~t​。学生只看到部分约束，却需要生成合理的动作。例如教师看到完整的伸手与身体运动，学生只看到右手目标和部分躯干条件。

一个简化蒸馏目标是：

Limit=Est∼dπS[∥πS(st,G~t)−πT(st,Gtfull)∥22]. \mathcal L_{\mathrm{imit}} =\mathbb E_{s_t\sim d_{\pi_S}} \left[\|\pi_S(s_t,\tilde G_t)-\pi_T(s_t,G_t^{\mathrm{full}})\|_2^2\right]. Limit​=Est​∼dπS​​​[∥πS​(st​,G~t​)−πT​(st​,Gtfull​)∥22​].

这个式子解释监督关系，省略了生成模型的潜变量与其他损失。它强调学生会经历自己执行动作后到达的状态，再获得教师指导，而不只是对一批固定专家状态做回归。

这对部署很重要。学生稍微偏离参考后，身体状态已经不同；如果训练从未覆盖这种偏移，误差可能继续累积。On-policy 蒸馏增加了在学生访问状态上学习纠正的机会。

这里仍有两个边界：教师需要能对这些状态给出有效动作；训练中的目标与扰动覆盖，也会限制学生能够应对的情况。On-policy 不等于能够恢复任意跌倒或实现任意新目标。

所给材料中的“10% episode 用教师动作，其余用学生 posterior 动作”属于特定公开单教师配置描述，待复核，不能直接视为最终发布模型的完整训练配方。

5. 为什么用条件 VAE：部分目标有很多种全身解

伸手到一个位置，可以通过肩肘运动完成，也可以伴随转身、下蹲或迈步。稀疏目标没有给出唯一的关节动作。

如果直接用一个确定性回归器拟合差异很大的示范，可能混合不兼容的运动解。条件生成模型的作用，是让这些不同解可以由潜变量表达，再由当前状态和目标选择合适的运动模式。

按所给材料，Metatron 的发布模型沿用 MaskedMimic 风格的条件 VAE，可概念性写成：

qϕ(zt∣st,Gtfull),pθ(zt∣ot,G~t),at=Dψ(ot,zt). q_\phi(z_t\mid s_t,G_t^{\mathrm{full}}), \qquad p_\theta(z_t\mid o_t,\tilde G_t), \qquad a_t=D_\psi(o_t,z_t). qϕ​(zt​∣st​,Gtfull​),pθ​(zt​∣ot​,G~t​),at​=Dψ​(ot​,zt​).

训练时，posterior 可以利用完整参考或特权信息；prior 学习只根据部署可获得的信息给出潜变量；decoder 将潜变量与状态转成动作。训练通常需要兼顾动作模仿和 prior/posterior 的分布对齐，具体形式应以实现为准。

条件 VAE 是学生的建模机制，不是完成蒸馏之后额外出现的第三个训练阶段。 项目页的第三步是冻结权重后的技能开发。

所给材料还列出 Spherical latent、6 层 Transformer、4 个注意力头、1024 hidden width、64 维 latent 与 29 维 raw actions。这些具体发布配置本次未能从模型卡复核，保留为实现核查项，不把它们当作理解方法所必需的已确认事实。

生成式训练也不要求每次部署都随机采样。运行时可以使用确定性的 prior 输出；是否采样、如何处理 latent 连续性，需要看具体部署版本。

6. 为什么稀疏目标可能有助于扰动恢复

当高层给出完整身体轨迹时，身体很多部位都承担跟踪任务。受到推力后，继续严格追踪这些目标，可能与临时迈步或摆臂恢复平衡发生冲突。

稀疏条件允许高层只保留当前最重要的要求，例如朝向和躯干目标，让其余自由度参与调整。闭环策略又会在每一步读取当前身体状态，因此能够根据偏移改变动作。

这提供了一个合理的机制解释：释放不必要的运动约束，可以给已有恢复能力留出发挥空间。

但 Mask 本身不会创造稳定性。恢复能力仍来自运动先验、训练中的状态覆盖和底层反馈。如果目标互相冲突、扰动太大，或者场景接触超出训练经验，策略仍可能失败。

对比实验需要同时控制参考质量、感知延迟、扰动方向、施力位置和持续时间，才能判断提升来自接口、模型能力还是上层目标设计。

7.1 物理接触真实，不等于任务全部自主

球的运动由碰撞产生，说明不是把球沿着预先写好的轨迹搬动。但任务仍可能有预知位置、定时释放和参考运动。

自主程度应沿着感知、目标生成、时序控制、运动执行分别检查。一个系统可以有真实动力学交互，同时使用大量由场景代码提供的信息。

7.2 “同一个策略”需要带上模型范围

官方页面说明，多项 G1 演示通过改变目标和掩码复用同一策略；SOMA 的滑行与攀爬使用另一套策略。页面还注明，场景几何仿真网格用的是单独的 sitting policy。

因此，不能把不同本体、场景演示和发布检查点合并成“一个权重已经展示全部能力”。后续评测应固定 checkpoint，并列清它支持的输入与任务范围。

9. 与 MaskedMimic、SONIC、VLA 的区别

MaskedMimic 提供了明确的方法基础。 2024 年的工作已经把物理角色控制建模为 masked motion inpainting，通过部分关键帧等条件生成全身运动，并讨论 goal engineering。Metatron 进一步把这类可提示控制放到机器人执行与 Agent 辅助技能开发中。MaskedMimic 官方项目

SONIC 强调大规模通用运动跟踪。 它也支持运动规划和多种输入接口，不能概括成只能死板回放完整动作。ARDY + SONIC 则由运动生成模块提供运动，再交给物理跟踪策略执行。Metatron 更强调在一个闭环策略接口中接受部分目标。SONIC｜ARDY 官方项目

VLA 负责的问题层级更高也不同。 Metatron 的结构化运动接口不自动解决从图像与语言识别任务对象、获取三维位置和判断操作完成的问题。

一个可组合系统可以是：

视觉与语言理解 → 任务计划 → 技能程序 → 运动目标 → Metatron → 机器人。

其中每一层都可能出错。执行层能够伸手到目标附近，并不代表系统已经理解了抓取方式、接触力和物体稳定性。精细操作还可以与 FACT、Tactile 中讨论的局部触觉控制结合，但这种组合需要新的接口与实验验证。

10. 这与 Skill Evolution 的关系最值得研究

把技能程序写成 fφf_\varphifφ​，它根据任务目标 GGG、当前状态和内部阶段生成运动约束：

(gt,mt)=fφ(st,G,phaset),at=πθ(ot,gt,mt). (g_t,m_t)=f_\varphi(s_t,G,\text{phase}_t), \qquad a_t=\pi_\theta(o_t,g_t,m_t). (gt​,mt​)=fφ​(st​,G,phaset​),at​=πθ​(ot​,gt​,mt​).

开发过程中保持 θ\thetaθ 固定，改进 φ\varphiφ：

φk+1=Revise⁡(φk,RolloutFeedback⁡(φk)). \varphi_{k+1}=\operatorname{Revise} \bigl(\varphi_k,\operatorname{RolloutFeedback}(\varphi_k)\bigr). φk+1​=Revise(φk​,RolloutFeedback(φk​)).

这样，改进的对象就可以被保存、比较和复用。例如跨栏失败后，修改接近距离阈值、参考时间对齐或落地恢复条件，不必重新跑一轮策略训练。

与已有的 InterEvolve 笔记 对照，可以区分两种程序接口：InterEvolve 围绕奖励程序与阶段逻辑组织任务；Metatron 的上层程序直接生成结构化运动目标。两者都要依赖底层已有的运动能力，不能把程序搜索等同于无限增加新的身体技能。

与 SuperMimic 的联系则在另一层：SuperMimic 重点讨论怎样通过可微世界模型高效训练控制器；Metatron 的 Agent 接口重点讨论训练好的控制器怎样被复用。训练效率和技能开发效率可以分别测量。

官方展示目前属于在人类指导下进行的技能开发。要进一步称为自主技能进化，还需要量化自动诊断、自动修复、留出场景泛化和长期技能库复用，不能仅凭代码发生了变化就认定完成了自主改进。

11. 怎样设计一个有说服力的 Agent 实验

以下是研究建议，并非项目已经完成的评测。

固定基础控制器和任务判定

所有方法使用同一 checkpoint、同样的初始技能、相同仿真预算和状态信息。Agent 可以修改目标生成与阶段逻辑，评估器独立判断任务是否成功。

任务判定和环境动力学应当固定。若 Agent 能修改碰撞设置、成功条件或直接移动目标物体，得到的改进就无法归因于更好的技能程序。

明确 Agent 能看到什么

是否提供障碍物精确坐标、物体速度、接触状态和失败原因，会显著改变问题难度。可以分别评测特权状态接口与感知估计接口，并避免混在同一个结果中。

同时衡量搜索效率与最终可靠性

指标 回答的问题
首次技能成功率 Agent 是否理解目标接口和任务结构
固定迭代预算后的成功率 执行反馈能否支持有效修改
仿真次数、时间与模型调用成本 改进需要多少资源
留出布局、速度、扰动下的成功率 是否只对开发场景有效
中途失败后的恢复率 技能是否形成了有效闭环
旧任务回归表现 新代码是否破坏已有技能
复用已有技能后的搜索成本 技能库是否积累了真正可迁移的知识

可以设置三组对照：固定目标模板、只调整数值参数的优化器、可以修改阶段结构的 Coding Agent。这样才能看清 LLM 的价值是语义分解和程序结构修改，还是仅仅完成了参数搜索。

分清“继续改代码”与“底层能力不足”

如果同一动作在合理目标、充分时间和不同参考下反复失败，原因可能是底层控制器没有对应能力。Agent 应当能够报告能力边界，而不是无限调整阈值。

一个成熟技能库可以保存适用条件、输入单位、反馈事件和已测试范围。保存一段成功代码只是起点，知道它在哪些条件下可用，才方便后续组合。
