Research notebook · 研究笔记

Mimir：记忆不只保存过去，还要支持下一步行动

机器人刚把杯子从桌上拿走，相机随后转向柜子。接下来，它需要知道的不只是“之前看见过一个杯子”，还包括杯子现在是否拿在手里、放置任务有没有完成，以及哪些寻找位置已经被证明不对。

Mimir 把这些信息显式分成 World Memory 和 Task Memory，再用 Dynamic Grounding 把当前目标绑定到世界中的具体对象。它关心的是行动所需的状态管理，而不只是保存更长的历史。

论文：Mimir: A Neuro-Symbolic Memory System with Dynamic Grounding for Embodied Agents in Interactive Environments。本笔记依据提供的解读，并对照论文 v1 核查任务记忆定义、完成条件和实验统计口径。

1. 为什么记得发生过什么，还会继续做错

完整历史里可能同时存在“杯子在桌上”“已经拿起杯子”“准备放进柜子”三种信息。模型每次重新读历史，需要区分过去状态、当前状态和未来意图。

长任务中，这种隐式重建容易导致重复执行已完成步骤、忘记前置条件，或反复去已经找错的位置。简单增加上下文长度，并不会自动解决这些状态更新问题。

Mimir 将记忆写为：

Mt=(Tt,Wt), M_t=(T_t,W_t), Mt​=(Tt​,Wt​),

其中 TtT_tTt​ 管理任务执行，WtW_tWt​ 管理世界实体与关系。两者分开更新，再通过当前目标连接。

2. World Memory：物体在哪里，依据是什么

World Memory 使用树形关系表达场景实体及其当前归属，例如房间、桌面、容器与手持状态。下面只是概念示意：

厨房
└─ 桌子
   └─ 红杯子
      └─ 证据：先前视觉观察

抓取效果得到确认后：
机器人手部
└─ 红杯子
   └─ 证据：抓取后的执行反馈

杯子离开视野，不意味着它从记忆中消失；发出抓取命令，也不意味着它已经移动到手里。更新需要由观察或执行效果支持。

因此，这份记忆是系统维护的场景判断，而不是全知的真实地图。证据过时、实体识别错误，都可能让记忆偏离现实。树形结构帮助组织信息，却不能替代感知本身。

3. Task Memory：目标是否真正完成

论文定义：

Tt=(G,⪯,st,ht,Ft,Ct). T_t=(\mathcal G,\preceq,s_t,h_t,F_t,C_t). Tt​=(G,⪯,st​,ht​,Ft​,Ct​).
字段 含义
G,⪯\mathcal G,\preceqG,⪯ 子目标与执行次序
sts_tst​ pending、completed 或 blocked
hth_tht​ 当前手持状态
FtF_tFt​ 被反馈否定的对象—来源位置假设
CtC_tCt​ 支持目标已完成的证据

这里需要修正附件的一处表述：原文的 CtC_tCt​ 是完成证据，不宜直接解释为约束集合。 系统确实处理执行约束，但不能因此改变这个符号的含义。任务记忆定义

尤其重要的是，动作接口返回 success，不等于当前子目标完成。导航到柜子成功，只说明导航动作成功；“把杯子放进柜子”仍需要相应的物体关系变化。

论文使用后置条件判断完成：只有执行反馈支持目标要求的状态变化，才将目标标为 completed。这使计划进度与实际效果联系起来，而不是根据“已经调用过接口”推进。

4. Dynamic Grounding：从候选记忆到可执行目标

假设当前目标是把红杯子放进柜子。记忆中可能有两个红杯子，其中一个以前出现在桌上，另一个在架子上。此时“找到了含有 red cup 的历史文本”还不够。

Mimir 将过程分为两步：

  1. Recall：根据当前目标，检索相关实体、来源关系和证据，保留候选。
  2. Grounding：结合当前观察、目标限制与失败记录，选择有依据的具体绑定，补足所需来源信息。

选择结果不仅包含物体名称，还包含当前要操作的实体、来源、目的地和依据。没有合法且有证据支持的绑定时，系统转入探索或失败处理，而不把一个猜测位置直接交给执行模块。

这也是失败记忆的作用：如果“红杯子在桌上”已经被新的交互否定，下一次不能只因同一条旧记录仍然存在，就重复采用这个绑定。

5. 记忆如何进入执行闭环

整体过程可以理解为：

观察更新世界 → 选择未完成目标 → 检索并绑定实体 → 规划抽象动作 → Embodiment Adapter 转成合法动作 → 执行反馈更新两种记忆。

Adapter 让上层计划和具体环境动作接口分离，但这不意味着一个规划器已经能无修改地控制所有机器人。动作语义、前置条件和反馈字段仍需要适配。

对真机而言，最值得注意的是反馈接口。例如抓取接口返回“运动完成”，不一定表示“物体抓取成功”。如果高层把这两种状态混淆，再清楚的记忆结构也会写入错误事实。

6. 实验数字要按统计口径读

下表是 Qwen3-VL-8B 在四类任务平均设置下的成功率：

设置 EB-ALFRED EB-Habitat
原始骨干 26.5% 28.5%
加入 Mimir 57.0% 65.0%
移除 World Memory 52.0% 12.5%
移除 Task Memory 34.0% 54.0%

这里的四类任务是 Base、Common-sense、Complex-instruction 和 Long-horizon。EB-Habitat 对 World Memory 的移除更敏感，EB-ALFRED 则更受 Task Memory 移除影响，说明不同任务的状态管理瓶颈不同。主表与消融

另外两组比较不能与此表直接混用：Qwen3-VL-32B 的 86.0% 是 EB-Habitat Long-horizon 子集结果；与 RoboMemory 的 90.0% 对 74.0% 使用 Qwen2.5-VL-72B，只平均 Base 和 Long-horizon。它们对应不同骨干和任务范围。

这些结果支持显式记忆在所测环境中的作用，但不直接证明底层抓取、接触控制或真机安全性得到改善。

7. 对长程机器人 Agent 的启发

这篇最值得借鉴的接口是：世界记忆说明“现在相信什么”，任务记忆说明“还有什么没完成”，grounding 说明“当前行动依据哪条世界证据”。这样失败时可以定位问题，而不是只看到一段越来越长的历史。

作为后续研究，可以固定骨干和调用预算，对比完整历史、结构化记忆、以及结构化记忆加失败绑定过滤。还可以人为移动已记住的物体，检查系统能否纠正旧位置，而不是持续重试。

这些是建议的实验。Mimir 主要处理单个 episode 内的状态维护，不等于跨 episode 学会新技能；它也无法恢复从未观察到的事实，或替含糊指令决定唯一正确对象。

与 PriorMaskMap 联系起来看，一个共同问题是历史信息什么时候值得相信；与 Move-Then-Operate 联系起来，上层记忆可以确定当前目标，下层专家可以执行动作。但连接两者时，仍要验证“动作结果如何变成可信的任务完成证据”，不能把这种组合设想写成已经验证的统一系统。
