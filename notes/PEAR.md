# PEAR：把一次完整的机器人尝试，变成推理模型的 RL 训练样本

**这篇最值得看的是训练闭环：一个已有视觉和推理能力的模型，在仿真中看图、思考、输出动作、看执行结果，直到任务结束；再用最终成败，更新整段交互中生成的推理与动作。**

论文：*Training Reasoning Models in Simulation to Natively Use Real Robots*，2026 年 11 月预印本。

[项目介绍](https://mit-han-lab.github.io/pear-blog/) · [官方论文](https://mit-han-lab.github.io/pear-blog/paper.pdf) · [代码](https://github.com/mit-han-lab/pear) · [本地论文备份](media/assets/PEAR/pear-paper.pdf)

这份笔记重点核对了论文 §3、Appendix A 的训练方法，以及 Appendix E 的完整评测。公式中的例子和研究建议属于解释与推导，会单独说明。

## 1. 先分清楚：PEAR 是系统，RURL 是训练方式

PEAR 的全称是 **Post-training Engine for Agentic Robotics**，是承载机器人后训练的基础设施。论文把这套训练方式叫作 **Robot-Use Reinforcement Learning，RURL**。

可以把它理解为：以前模型用浏览器、终端，通过工具返回结果继续思考；这里把工具换成机器人接口，返回的是动作执行后的图像和机器人状态。

模型学的内容因此包括几部分：看懂当前场景、决定下一步、选择动作幅度，以及在执行偏差发生后调整策略。这些行为一起由任务结果监督。

它从预训练好的 **Qwen3.8-27B 推理 VLM** 出发。这套机器人训练配方没有先用任务示范做 SFT，也没有依赖机器人示范轨迹来启动 RL。但这不意味着模型从零学视觉、语言和空间概念，更不意味着基座的预训练没有使用过人类数据。

论文没有给模型额外接一个 diffusion/flow action expert。模型仍通过自回归生成输出：前面是推理，后面是结构化动作。机器人动作成为模型输出语言的一部分。

## 2. 一条训练样本到底长什么样？

这里的样本是一整段 episode，而不是一张图对应一个动作。

假设任务是把杯子放进碗里。模型先收到任务描述、机器人接口说明、相机图像和机械臂状态，然后开始交互：

```text
任务 + 机器人说明 + 当前图像与状态
  ↓
模型生成推理：杯子在哪里，夹爪该怎么靠近
  ↓
模型输出 JSON 动作：末端位移、旋转变化、夹爪控制
  ↓
控制器执行 → 仿真环境推进
  ↓
返回新图像与状态
  ↓
模型结合完整历史继续推理、继续动作
  ↓
任务成功，或触及终止条件
  ↓
得到整个 episode 的奖励 1 或 0
```

论文动作接口中的平移与旋转是**变化量**，平移单位为厘米，旋转单位为弧度，并带有夹爪控制。动作执行后，控制器等待目标到达且机器人停止运动，或者判断机器人受阻、无法继续接近目标，再返回观测。

这点很关键：VLM 的一次输出对应一个机器人运动指令，底层控制器负责把它落实为关节运动。VLM 没有逐毫秒输出电机力矩。

不同平台的控制器也不同：LIBERO 的 Franka 使用 operational-space controller；RoboDojo 的 ARX 使用笛卡尔路点与逆运动学；真实 YAM 则接入对应的机器人控制实现。因此，作者强调的原生 robot-use 仍然有动作解析、执行器和环境反馈这些基础设施。

一条 episode 会在以下情况结束：仿真器判定成功、达到环境步数限制、耗尽上下文预算，或者模型的响应中没有有效动作。早先各轮的图像、状态、推理和动作保留在上下文里。来源：[论文 §3.1、Appendix A](https://mit-han-lab.github.io/pear-blog/paper.pdf)。

## 3. 到底反传什么？仿真器需要可微吗？

不需要可微仿真器。

设第 \(t\) 轮历史为 \(h_t\)，模型生成响应 \(y_t\)：

$$
y_t\sim\pi_\theta(\cdot\mid h_t).
$$

响应中包含推理文本和动作文本。环境执行动作后返回新的观测，继续构成下一轮的历史。最后得到：

$$
\tau=(o_1,y_1,o_2,y_2,\ldots,o_T,y_T).
$$

训练优化的是“在这些历史条件下，模型生成这些 token 的概率”。环境只需要能执行动作、返回观测和检查成功；梯度不会穿过碰撞检测、IK 或物理积分器。

例如，一次尝试成功了，训练会相对提高这次尝试中生成内容的概率；另一次在相同初始条件下失败了，就相对降低它生成内容的概率。这是策略梯度的基本思路。

**更新模型策略不等于论文已经说明了每个模块的冻结配置。** 论文的训练表没有完整列出视觉编码器、投影层和语言模型的 optimizer parameter groups。这份笔记不据此断言“全部 27B 参数都更新”或“视觉编码器一定冻结”；具体复现时需要检查代码配置。

## 4. 奖励非常简单：整个任务完成了没有

论文使用终局二值奖励：

$$
R(\tau)=
\begin{cases}
1,&\text{episode 结束前仿真器报告成功},\\
0,&\text{否则}.
\end{cases}
$$

没有为“夹爪离目标近一点”“推理说得合理”“轨迹看起来平滑”分别设计密集奖励。模型获得的主要信号，就是完整尝试是否完成了任务。

这让目标比较直接，也把难点暴露出来：一个已经能偶尔成功的模型，可以比较成功与失败；一个从来没成功过的模型，几乎得不到有区别的信号。

所以这篇训练的真正支点，是**基座的初始能力、组内比较、有效组筛选和课程安排**。奖励公式本身只有一行。

## 5. 同一个任务、同一个初始状态，尝试 8 次

每组包含 8 条完整 episode，它们共享任务和初始状态，再通过采样产生不同的推理与动作。

为什么要固定初始状态？因为这样可以更直接地比较“这个场景下，哪种尝试更有效”。如果把简单场景中的成功和困难场景中的失败随意放在同组，奖励差异就会混入任务难度。

PEAR 使用 GRPO 风格的组内归一化优势：

$$
\hat A_i=
\frac{R_i-\operatorname{mean}_j R_j}
{\operatorname{std}_j R_j+\epsilon}.
$$

例如，一组结果是：

```text
成功，失败，失败，成功，失败，失败，失败，失败
```

按总体标准差计算、暂时忽略 \(\epsilon\)，均值是 0.25，标准差约为 0.433：

- 成功 episode 的优势约为 \(+1.732\)。
- 失败 episode 的优势约为 \(-0.577\)。

这些数值只是帮助理解的算例，具体实现还需注意标准差采用的约定。

### 优势给整条轨迹中的哪些部分？

**同一条 episode 中，所有轮次生成的 token，都使用同一个 episode advantage。** 无论这个 token 属于推理，还是属于动作 JSON。

因此，模型的推理输出也接受任务成败监督。但这里没有一个单独的推理打分器来判断每句话对不对，也没有逐轮指出“第 7 步抓错了”。这是稀疏的整轨迹信用分配。

图像、环境返回的状态、system prompt 等输入内容，不作为模型生成的 action token 来计算这项策略损失；它们仍然是模型预测时的条件。不要把“输入 token 不直接计策略损失”理解成“处理这些输入的网络模块一定没有梯度”。

### token-mean 还有一个容易漏掉的细节

论文对整个 batch 的生成 token 求平均，而不是先对每条 episode 求平均再平均 episode。

所以，在优势相同的情况下，一条生成内容更长的 episode 会贡献更多项。它不是显式的长度奖励，却会影响不同轨迹的相对权重。训练后轨迹变短，也不能直接说成作者加了“少思考奖励”。来源：[论文 §3.2、Table 1](https://mit-han-lab.github.io/pear-blog/paper.pdf)。

## 6. 为什么丢掉全成功和全失败的组？

因为这两类组的奖励没有差异，组内优势都为零。

```text
1 1 1 1 1 1 1 1 → 没有相对优势
0 0 0 0 0 0 0 0 → 没有相对优势
1 0 0 1 0 0 0 0 → 有学习信号
```

PEAR 沿用 DAPO 的组过滤思路：丢掉全成功或全失败的组，重新采样补足 batch。

论文的 **128 组 × 8 条 = 1,024 条 episode/update，是过滤后保留的数量**。为了拿到这些有效组，实际执行的 episode 会更多。

做一个简化估算：假设某个初始状态下，每次尝试独立成功的概率都是 \(p\)，那么 8 次中既有成功又有失败的概率是：

$$
P_{\mathrm{valid}}=1-p^8-(1-p)^8.
$$

| 单次成功概率 | 有效组概率，约 |
| --- | ---: |
| 0.4% | 3.16% |
| 2% | 14.92% |
| 50% | 99.22% |

例如 \(p=2\%\) 时，平均需要采约 858 组，才得到 128 个有效组，也就是约 6,862 条 episode。**这是独立同分布假设下的解释性估算，不是论文报告的真实采样量。** 不同初始状态的难度不同，也会改变实际比例。

这个例子解释了两件事：低成功率时，过滤会显著放大 rollout 成本；而成功率严格为零时，重新采多少组都不能凭空生成正样本。

另一个值得观察的现象是，过滤后的训练分布可能更偏向那些“已经有一定成功机会”的任务。这是根据机制作出的推断，需要记录各任务的原始采样数与保留数来验证。

## 7. 课程学习：先把偶尔能做成的事练稳

初始模型在 LIBERO 的 Goal、Spatial、Object 三套任务上大约有 2% 的成功率，在 LIBERO-Long 上只有约 0.4%，多数 RoboDojo 任务则几乎无法成功。

作者没有一开始就把全部难任务放进去，而是按下面的顺序训练：

| 阶段 | 更新步数 | 任务 | 目的 |
| --- | --- | --- | --- |
| 第一阶段 | 1–148 | LIBERO Goal、Spatial、Object | 利用已有的少量成功，建立基本操作能力 |
| 第二阶段 | 149–225 | 加入 LIBERO-Long，训练全部四套 | 在迁移产生成功机会后学习长任务 |
| 第三阶段 | 226–340 | RoboDojo 的 general_pickup、align_blocks | 跨平台继续适配两个有较强信号的任务 |

第一阶段结束时，尚未直接用于训练的 LIBERO-Long 成功率已经达到约 39%。这意味着先前任务学到的能力，确实让更难任务开始提供可用的奖励差异。

所以课程的逻辑很具体：

**先找模型偶尔能做成的任务 → RL 提高基本能力 → 检查更难任务是否开始出现成功 → 再把它纳入训练。**

这也限定了“仿真 RL 自己学”的含义。模型没有自动发现任意机器人技能，任务选择和课程设计仍然由研究者组织；第三阶段只训练了两个 RoboDojo 任务。来源：[论文 §3.3、§4、Appendix A](https://mit-han-lab.github.io/pear-blog/paper.pdf)。

## 8. 它用了 GRPO，但不要直接套 PPO loss

这是读这篇最容易误解的地方。PEAR 使用 GRPO 的组内优势，同时使用 **REINFORCE policy loss 的 bypass 路径**。论文明确写了：

- 没有 PPO clipping。
- 没有 KL penalty。
- 没有 entropy bonus。
- 异步策略差异使用 score centering，不使用 truncated importance sampling。

因此，把它的训练公式直接写成 clipped probability ratio 的 PPO 目标，会偏离本文实际配方。

### 为什么需要处理异步？

机器人 rollout 很长。若每次都等待所有 episode 跑完，再统一更新、统一开始下一批，训练卡就容易等待采样。

PEAR 让 rollout 和模型更新完全异步。负责生成轨迹的策略记为 \(\mu\)，当前训练策略记为 \(\pi_\theta\)。论文中，前者通常落后一到两个参数版本。

也就是说，正在训练的模型看到的轨迹，可能来自稍旧的自己。

### score centering 减掉什么？

定义一个 token 的 score function：

$$
s_\theta(y,c)=\nabla_\theta\log\pi_\theta(y\mid c),
$$

其中 \(c\) 是当前 token 的完整上下文。论文采用的梯度估计可以写成：

$$
g=\frac{1}{N}\sum_i\hat A_i\sum_{t,k}
\left[
s_\theta(y_{i,t}^k,c_{i,t}^k)
-\mathbb E_{v\sim\mu(\cdot\mid c_{i,t}^k)}
s_\theta(v,c_{i,t}^k)
\right].
$$

\(N\) 是 batch 中的生成 token 总数。第一项是实际采样 token 的 log-probability 梯度；第二项是在旧 rollout 策略的下一 token 分布下，这个梯度的期望。

直觉上，它把“实际选到这个 token 对应的梯度”，与“旧策略在这里通常会产生的平均梯度”作比较。

如果采样策略与当前策略相同，有熟悉的恒等式：

$$
\mathbb E_{v\sim\pi_\theta}
[\nabla_\theta\log\pi_\theta(v\mid c)]=0.
$$

因为所有 token 的概率加起来恒等于 1。换成旧策略 \(\mu\) 来取期望后，这个量一般不再为零；score centering 就显式减掉它。来源：[论文 §3.2，公式 2](https://mit-han-lab.github.io/pear-blog/paper.pdf)。

### 如果想对应到一个 loss

把优势、采样上下文和旧策略分布视为固定量，一个与上式梯度对应的说明性写法是：

$$
\mathcal L=-\frac{1}{N}\sum_{i,t,k}\hat A_i
\left[
\log\pi_\theta(y_{i,t}^k\mid c_{i,t}^k)
-\sum_v\operatorname{sg}[\mu(v\mid c_{i,t}^k)]
\log\pi_\theta(v\mid c_{i,t}^k)
\right].
$$

这里 \(\operatorname{sg}\) 表示 stop-gradient。这个式子用于解释梯度关系，不是声称仓库逐字实现了这段计算。

尤其需要注意：旧策略在“实际采样 token”上的单个 logprob，不能直接提供对完整词表分布的期望。复现时应核对代码如何得到或估计这个期望，而不能只保存 old logprob 就宣布实现完成。

另外，这个条件期望的中心化操作，不应被扩大解释为“整个异步长轨迹梯度已严格恢复为无偏 on-policy 梯度”。轨迹状态分布也来自旧策略。本文这里保留方法本身的边界。

## 9. 把一次更新完整串起来

下面是概念伪代码，实际系统中采样和更新是并发流水线：

```python
groups = []
while len(groups) < 128:
    task, initial_state = sample_from_current_curriculum()
    episodes = []

    for _ in range(8):
        # 各次 reset 到同一个任务初始状态；生成具有随机性。
        trajectory = rollout_until_end(
            rollout_policy,
            task=task,
            initial_state=initial_state,
            temperature=1.0,
            reasoning_effort="xhigh",
        )
        episodes.append(trajectory)

    rewards = [int(ep.simulator_success) for ep in episodes]
    if all(r == 0 for r in rewards) or all(r == 1 for r in rewards):
        continue

    advantages = group_normalize(rewards)
    groups.append((episodes, advantages))

# 一条完整 episode 对应一条训练序列。
# 只把各轮模型生成的 token 放入 policy-loss mask。
# 所有生成 token 使用所属 episode 的优势。
loss = score_centered_policy_loss(
    current_policy,
    groups,
    reduction="generated_token_mean",
)
optimizer.zero_grad()
loss.backward()
optimizer.step()
# 新参数发布给 rollout 系统；旧版本在途轨迹可能仍继续完成。
```

这里省略了调度、padding、序列并行、行为策略版本记录，以及 score-centering 期望的实际实现，不能当作可直接运行的复现代码。

## 10. 算法不复杂，长上下文训练才是真正贵的部分

论文报告，一条 episode 平均约有 **94k tokens、19.7 轮交互、39–59 张图像**；其文本统计口径约为 1.8k prompt tokens 和 92k response tokens。

也就是说，它的成本不只是“跑几次机器人动作”，还包括长推理生成、不断增长的多轮视觉上下文，以及把完整交互序列拿来做反向传播。

| 项目 | 论文配置 |
| --- | --- |
| 优化器 | AdamW |
| 学习率 | \(10^{-6}\) |
| 每步更新 | 一次参数更新 |
| 有效 batch | 128 组，每组 8 条 episode |
| 采样 | Temperature 1.0，完整分布采样 |
| 推理强度 | 训练全程 xhigh |
| 训练序列上限 | LIBERO 256k；RoboDojo 160k |
| 损失归一化 | batch 内生成 token 的均值 |
| 总训练成本 | 约 50,000 H100-equivalent GPU-hours |

这些是论文报告的配置和算力折算量，不是本笔记复现实测，也不是可直接换算的账单。来源：[论文 Appendix A，Table 1](https://mit-han-lab.github.io/pear-blog/paper.pdf)。

### Rollout 端：尽量复用历史前缀

每次追加一轮交互，前面的大量上下文都没有变化，KV cache 复用非常重要。

H100 配置使用 TP=4，并通过 LMCache 把历史前缀 KV cache offload 到 CPU。论文控制并发量以维持约 95% 以上的前缀命中率：160k 上限时每引擎并发 64 条，256k 上限时并发 32 条。

这些是单个推理引擎的并发配置，不能理解成每张卡都能独立并发这么多条。GB300 配置则使用 TP=2，而且因主机内存限制没有使用 LMCache。

### Training 端：整条 episode 做一条序列

H100 使用 8 卡 FSDP 配合 8 路 sequence parallel，每卡承担 32,512 tokens，并结合 FlashAttention-3、activation offloading 和 gradient checkpointing。

GB300 使用 4 卡 FSDP 配合 4 路 sequence parallel，每卡 69,632 tokens，使用 FlashAttention-4 和 gradient checkpointing。

**FSDP8 × SP8 在这里不是需要 64 张卡的乘法。** 论文说明每个节点组成一个 FSDP group，同一组卡还承担序列并行；H100 这里对应 8 卡节点。

LIBERO 在 rollout 节点使用 CPU 渲染，RoboDojo 的 Isaac 容器在单独的 GPU 节点运行。一次完整训练因此需要同时考虑模型采样、模型反传和环境仿真三类资源。

## 11. 结果应该怎样看？

### 基本操作确实能从稀疏成功中长出来

LIBERO-only checkpoint 的平均成功率从基座的 **1.6% 提高到 74.4%**。但论文比较中的 \(\pi_{0.5}\) 在域内达到 96.9%，因此这不是“纯 RL 在所有条件下超过动作模型”的结果。

PEAR 的优势更明显地出现在部分任务变化：LIBERO-Pro 的 task 扰动下，论文模型为 57.4%，对照 \(\pi_{0.5}\) 为 0.75%；position 扰动为 57.5% 对 20.8%。而 semantic、object 等扰动类型中，对照模型仍更强。

这更像是不同训练路线形成了不同的泛化特性，需要按扰动类型拆开看。来源：[论文 §4，Figure 4](https://mit-han-lab.github.io/pear-blog/paper.pdf)。

### 真机迁移有结果，但测试范围很小

论文在真实机器人上的 30 次尝试中，基座、LIBERO-only、最终模型分别成功 0、7、18 次，即 0%、23.3%、60%。

这说明在所测试任务中，仿真后训练得到的能力可以迁移到真实机器人。但任务范围仍围绕两个重点任务；新平台与新物理环境的迁移，不能自动等同于对任意未见任务的泛化。

### 两个任务上的 75%，不是完整 RoboDojo 的 75%

这一点值得单独记下来。Appendix E 给了完整 RoboDojo 结果：42 个任务，其中 12 个泛化任务分别测标准与随机设置，总计 **54 个设置、540 条 episode**。

最终模型成功 **21/540 条**，原始汇总比例约为 **3.89%**。官方指标先在能力维度内平均，再对五个维度平均，得到 **5.50%**；两者统计口径不同。

21 次成功分别来自：

- general_pickup：8 次。
- align_blocks：7 次。
- match_and_pick_from_conveyor：3 次。
- solve_equation：3 次。

其中前两个正是第三阶段训练任务。**370/540 条 episode，也就是 68.5%，因耗尽 256k 上下文而失败。** 这里的 256k 是完整评测的上下文窗口，不要与 RoboDojo 训练时的 160k 上限混淆。

所以这项工作证明了可行的学习与迁移路径，也直接暴露了长任务限制。它还没有把一个 27B 模型训练成能够稳定解决全套开放机器人任务的通用策略。来源：[论文 Appendix E，Figure 11](https://mit-han-lab.github.io/pear-blog/paper.pdf)。

## 12. 对“推理有用”的理解也要具体

LIBERO-only 模型在 low 推理强度下为 21.9%，xhigh 下为 74.4%。训练本来就全程采用 xhigh，因此测试时大幅减少推理预算会带来明显下降。

这支持“这套策略依赖较大的推理预算”这个判断，但没有直接证明每段可见推理都忠实表达了动作决策的因果过程。

更值得关注的是：模型训练初期每条 episode 约 119k tokens、19.9 轮，后期约 82k tokens、18.5 轮。任务表现提高时，生成量也在下降，但交互轮数变化没有那么大。

一种可能解释是模型减少了无效分析或更快作出决策；要确认它到底省掉了什么，还需逐轮分析 token、动作、等待与失败恢复行为。不能仅凭长度变化给出机制结论。

## 13. 如果自己做类似训练，先验证哪几件事？

### 先检查模型有没有“偶尔能成功”的起点

在最小任务集上，用与训练一致的动作接口和推理预算测试基座。记录最终成功率，也记录动作解析失败、控制器无法到达、上下文耗尽分别占多少。

如果任务从来没有成功过，直接扩大 GRPO batch 很可能只会得到更多全失败组。应先缩小任务难度、改善接口说明、检查坐标系与动作范围，或者明确引入额外监督；后者属于改变训练配方，需要单独记录。

### 再检查组采样和 loss mask

必须确认同组初始状态确实一致、组间任务采样符合课程配置、只在生成 token 上计算策略损失，以及一条 episode 的各轮输出对应了同一个正确优势。

这些问题一旦出错，模型可能仍有 loss 曲线，却不再学习预期目标。

### 最后再扩大异步和长上下文

先用较小配置验证同步的采样—更新闭环，再核对异步版本记录与 score-centering 实现。尤其要查清：行为策略分布如何获得、在途轨迹版本如何关联、过滤组占比是多少，以及是否出现某些任务长期无法进入有效 batch。

监控至少同时覆盖成功率、有效组比例、每条轨迹 token 数、失败原因和实际 GPU-hours。只看最终保留的 1,024 条轨迹，会漏掉大量无效采样成本。

以上是根据论文提出的复现顺序，不是作者原文提供的完整操作手册。本笔记没有运行训练，也没有验证仓库在本机的安装兼容性。

## 14. 对 RUA / 机器人 Agent 的启发

PEAR 给出了一个相当清楚的连接：**把机器人交互定义为稳定的工具协议，就可以把通用推理模型的 agentic RL 延伸到物理任务。**

它的训练单元包含观察、决策、执行和再次观察。对于失败恢复，这种训练单元很有吸引力：抓空后重新定位、发现放置位置不对后调整，理论上都能作为成功轨迹中的行为得到强化。

但终局二值奖励不会自动告诉模型恢复动作为什么有效。若某类失败状态从未被采到，或者几乎无法恢复成功，当前配方仍缺乏信号。要研究恢复能力，适合单独构造恢复初始状态，并分开报告正常任务成功率和恢复成功率。

完整 RoboDojo 中的大量上下文耗尽，也说明动作能力与长程信息管理需要一起考虑。历史压缩、选择性记忆、减少重复推理都有潜在价值，但加入这些模块后应作为独立变量评测，不能把新增系统能力归给原始模型。

我最想从这篇接着研究三个问题：

1. **什么基座能力决定 RL 能不能启动？** 对同一任务比较视觉定位、动作格式与初始成功率，找出稀疏奖励开始有效的条件。
2. **成功轨迹真正教会了哪些恢复行为？** 在固定失败状态集上测试，区分偶然成功与可重复的反馈修正。
3. **怎样在相同成本下走得更远？** 同时控制模型大小、推理 token、环境交互和训练预算，比较完整任务完成率，而不是只比短任务上的峰值数字。

读完这篇，可以把它的训练记成一句话：**从有能力偶尔成功的推理 VLM 出发，用同场景多次尝试产生相对优势，通过课程和有效组筛选持续获得信号，再用长上下文、异步 RL 系统把整段机器人交互学进去。**
