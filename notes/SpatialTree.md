# SpatialTree：空间能力怎么拆开测，又该怎么一起训练？

SpatialTree 研究的是一个很实际的问题：**一个模型空间题答得不好，到底缺了哪种能力？补距离、大小或跨视角对应关系，能不能让它更会规划和行动？**

作者先提出四层能力分类，再用 SpatialTree-Bench 测量这些能力，最后通过 SFT 和 RL 改变训练内容，观察收益会迁移到哪里。它最有价值的部分，是把“空间智能更强了”拆成可分析的能力变化。

读完可以先记住三件事：基础空间技能之间并不总能互相带动；多种技能联合训练在实验中优于单独训练；感知题与复杂规划题对显式推理的需求不同。这里的证据主要来自多模态模型评测，迁移到真实机器人闭环控制还需要进一步验证。

论文：**SpatialTree: How Spatial Abilities Branch Out in MLLMs**。作者为 Yuxi Xiao、Longfei Li、Shen Yan、Xinhang Liu、Sida Peng、Yunchao Wei、Xiaowei Zhou、Bingyi Kang，来自浙江大学、ByteDance Seed、北京交通大学。

[论文](https://arxiv.org/abs/2512.20617) · [全文 HTML](https://arxiv.org/html/2512.20617v2) · [PDF](https://arxiv.org/pdf/2512.20617v2) · [项目主页](https://spatialtree.github.io/)

版本说明：文中的解释性例子、简化公式和研究建议不等同于作者完整实现。

## 1. 这篇 benchmark 有什么用？

假设两个模型在机器人任务上都是 40% 成功率，它们可能有完全不同的问题。

一个模型看不准杯子的深度，计划正确却总是抓空；另一个能定位杯子，但不记得刚才把目标容器放在哪里。只看最终成功率，两者没有区别；换一种训练数据，效果却可能完全不同。

SpatialTree 想提供一张能力分布表：分别测空间感知、语义理解与记忆、空间推演，以及行动相关能力。这样可以回答：

- 改进发生在哪个能力分支？
- 训练某种基础技能之后，其他技能受益还是退化？
- 总分上涨是否掩盖了某个关键能力下降？
- 哪些任务适合直接回答，哪些任务值得多花推理计算？

这更接近模型训练与评测的诊断工具。真实部署前，仍然需要执行评测，因为空间题分数只能覆盖操作能力的一部分。

## 2. 四层空间能力，究竟怎么区分？

L1–L4 是作者对任务能力的分类，不是神经网络的四个模块，也不意味着模型必须按四阶段顺序训练。

| 层级 | 核心问题 | 杯子操作中的例子 |
| --- | --- | --- |
| L1 Perception | 当前观测中的几何和运动是什么？ | 杯子在哪里、多远、朝哪边倾斜？ |
| L2 Mental Mapping | 这些观察有什么含义，怎样组织和记住？ | 哪部分可抓；转动相机后杯子还是原来那个吗？ |
| L3 Mental Simulation | 如果这样操作，接下来会发生什么？ | 直接搬杯子会撞到遮挡物吗；应该先挪哪个物体？ |
| L4 Agentic Competence | 怎样根据任务和观测选择行动？ | 给出移动、旋转、抓取或导航动作。 |

杯子例子用于理解分类，并非原文所有任务都在控制同一个机器人。

### L1：感知也有很多种

L1 包含五组、11 项细分能力：

| 分组 | 细分能力 |
| --- | --- |
| Geometry | Distance、Size、Shape |
| Motion | Egocentric Motion、Allocentric Motion |
| Orientation | Gravity、Object Orientation |
| Relation | Topology、Correspondence |
| Localization | Detection、Grounding |

Egocentric Motion 是观察者自身运动，Allocentric Motion 是外部物体运动。画面中的车往左移，可能是车动了，也可能是相机动了，二者需要区分。

Topology 关注包含、重叠等基本空间配置；Correspondence 关注跨视角的同一物体或位置。知道两张照片都出现了椅子，与知道其中哪两把椅子是同一个实体，要求不同。

L1 也包含深度、三维定位、朝向等困难视觉任务。“基础”表示它在能力体系中的位置，不表示它容易解决。

### L2：从局部观察变成有语义、可检索的空间知识

L2 分成 Understanding 和 Memory，共七项细分能力。前者包括空间描述、关系理解、运动理解、视角转换和 Affordance；后者包括 Cognitive Map 与 Memory Retrieval。

比如“这个物体有一个弯曲突出部位”偏几何描述，“这个部位可以握住并提起杯子”就涉及可供性。再比如相机离开桌面后仍能回答钥匙的位置，就需要利用之前的观察。

这里的认知地图是能力目标。模型可能通过上下文隐式完成，也可能借助某种显式表示；分类本身没有指定必须使用 BEV、点云或场景图。

### L3：把关系用于推演和规划

L3 包括因果推理与序列规划，共五项细分能力。重点从“世界是什么样”转到“满足规则的变化会怎样发生”。

一个直观例子是积木重排：知道每块积木的位置还不够，需要考虑移动后有没有支撑、是否占据目标位置、操作顺序是否可行。

这些题可以通过视觉问答与规则推演测量。答对不意味着模型内部一定有可持续滚动、物理一致的生成式世界模型；这里测到的是推演结果。

### L4：把空间信息用于目标执行和探索

L4 包括 Goal-Driven Execution 与 Open-World Exploration，共四项细分能力，覆盖导航、操作、知识获取和自主设定目标等方向。

这层离 Agent 最近，但要分清两件事：作者希望描述的完整行动能力，以及 benchmark 实际能够测到的代理任务。后者包括从图像预测动作序列、在视频帧中选择动作、判断任务进展等。

因此四层可以作为能力组织方式，不能直接理解成一条已经证明的认知发展因果链。

## 3. Benchmark 数据是怎样构建的？

SpatialTree-Bench 覆盖 27 项细分能力、41 种评测任务。作者重新组织已有数据集，并用 SpatialPlus 补充覆盖不足的能力。

### L1：把视觉模型的输出变成可提问的空间标签

例如先得到深度图、对应关系、相机重力方向或物体朝向，再用模板生成问题，最后通过语言模型改写。

论文使用的专家模型包括 Depth Anything 3、SpatialTracker、GeoCalib 和 OrientAnything。可以把流程概括为：

```text
图像或视频
  → 专家视觉模型提取空间信息
  → 按能力设计问题与答案
  → 模板与语言改写
  → 空间问答样本
```

优势是生成效率高，能够覆盖连续数值、跨视角关系等人工标注成本较高的任务。相应地，部分标签属于专家模型的估计值。模型在这些题上与参考答案一致，不等于已经获得真实测量级的几何精度。

### L2：先整理场景，再构造地图和记忆问题

作者利用三维重建流程，从多视角或视频生成 BEV 等场景信息，再构造描述、认知地图和记忆检索问题。

要区分标注者的信息与被测模型的信息：构造答案时可以用完整重建结果，被测模型的输入未必包含这张地图。任务是在检查模型能否从给定观察中恢复相关知识。

### L3：已有规则与推理数据，加上结构化问答

几何变换、运动和规划题来自已有标注资源，再通过模板和语言模型补充或改写推理表达。

这类题目的判断依赖规则和最终答案。模型生成一段流畅的解释，不能自动算作空间推演正确；评测需要检查它是否满足题目约束。

### L4：把运动记录转成语言模型可表达的动作

Spatial Action Mapping 将相机运动、手部动作或机器人动作映射成统一、可输出的形式。

导航可以使用前后、左右、上下平移以及旋转原语；机器人夹爪任务使用末端平移、旋转与夹爪开闭；人手任务还涉及 Push、Pull、Grab 等交互原语。

这里的统一主要发生在接口和评测层。它让不同 MLLM 能输出可解析答案，并不意味着这些模型都经过了机器人低层控制训练。

## 4. L4 的分数，为什么不能直接叫任务成功率？

考虑一段参考轨迹：机械臂向左移动 5 厘米，再向前移动 3 厘米。模型输出与它接近，动作对齐分数就可能较高。但环境里也许有另一条绕行路径同样成功；反过来，贴近示范的轨迹也可能因物体位置微小变化而失败。

**参考动作相似度与闭环任务成功，回答的是两个不同问题。**

论文对部分导航、操作任务，计算预测动作与 Ground Truth 的距离和方向一致性。其平移评分为：

$$
s_d=\max\left(0,1-\frac{\|\Delta p_{\mathrm{pred}}-\Delta p_{\mathrm{gt}}\|}{\|\Delta p_{\mathrm{gt}}\|}\right),
$$

$$
s_\theta=\frac{\Delta p_{\mathrm{pred}}\cdot\Delta p_{\mathrm{gt}}}{\|\Delta p_{\mathrm{pred}}\|\|\Delta p_{\mathrm{gt}}\|},
\qquad s_{\mathrm{step}}=s_d\max(0,s_\theta).
$$

方向与位移量都接近参考，分数才高。旋转另用旋转矩阵之间的角度误差，夹爪开闭用分类正确性。

这个度量适合检查动作几何是否合理，但真实执行还涉及碰撞、可达性、接触、反馈和路径多解。公式遇到零位移时也需要实现层明确处理规则，不能不加判断地直接照抄。

此外，41 种任务的评测方式中约 70.7% 为选择题。这是**任务类型的占比**，不要直接写成全部测试样本的 70.7%。选择题便于自动评测，但提供候选项也会改变任务难度。

真正的闭环测试至少需要：模型动作改变环境，环境返回新观测，模型再根据实际结果选择下一步。视频中的动作选择和轨迹预测有诊断价值，但不能替代这个闭环。

## 5. 作者怎么研究能力之间的关系？

先让多个 MLLM 完成各类任务，得到每个模型的能力分数向量，再计算不同能力在模型之间的 Pearson 相关性。

如果擅长能力 A 的模型通常也擅长 B，A、B 的相关系数就高。结果中，L1 内部相关性相对较弱，L3、L4 的一些能力相关性更强。

作者的解释是：基础技能有较强专门化，高层任务需要组合多个基础技能，因此彼此关联更强。

这个解释合理，但相关性还可能来自共同因素：模型规模、通用推理能力、预训练数据、输出格式稳定性。它也不能告诉我们方向——A 提高导致 B 提高，还是两者共同受 C 影响。

所以后续训练干预更关键：有意增加某类空间数据，看模型其他能力是否变化。这比单纯看相关矩阵更接近“补哪种能力有用”的问题。

## 6. SFT 实验：怎么训练，又迁移到了哪里？

### 6.1 数据配方

作者选择 Distance、Size、Correspondence 三种 L1 能力，每类构造约 25 万条能力专用样本。

距离题利用 SUNRGBD、Hypersim、Matterport3D 等数据；大小题使用带三维框标注的数据，包括 SUNRGBD、Hypersim、ARKitScenes；对应关系数据参考 VST 的方案构造。

能力专用数据与通用多模态指令数据按约 **1:3** 混合。通用混合包含单图、多图、视频和三维任务。作者还设置仅用通用数据、token 消耗相同的 SFT baseline，用来减少“只是多训练了一些 token”的解释。

SFT 可以用标准监督目标理解：

$$
\mathcal L_{\mathrm{SFT}}=-\mathbb E_{(x,y)\sim D}\sum_t\log p_\theta(y_t\mid x,y_{<t}).
$$

这里 $x$ 是视觉输入和问题，$y$ 是目标回答。这个公式解释训练形式；论文主要改变的是能力数据组合，不是提出一种新的 SFT 损失。

### 6.2 单能力训练：局部进步不等于整体变强

| SFT 配方 | 总分 | 相对通用 SFT baseline |
| --- | ---: | ---: |
| 通用 baseline | 25.0 | — |
| 加 Distance | 24.5 | −0.5 |
| 加 Correspondence | 25.2 | +0.2 |
| 加 Size | 23.5 | −1.5 |
| Distance + Size + Correspondence | 26.1 | +1.1 |
| 再加入 Motion | 27.3 | +2.3 |

来源：论文 Table 2。这里是加权 benchmark 分数，变化用“分”表达，不等于所有任务的成功率变化。

Distance 训练后，Geometry 从 20.9 到 24.1，但 Relation 从 28.9 到 23.2，Localization 从 24.2 到 19.6；与此同时，Goal-driven Execution 从 22.1 到 25.5。

也就是说，总分略降，某些高层分支却变好。仅看总分会漏掉迁移效果，仅挑一个上涨分支又会漏掉能力退化。

Correspondence 也有类似现象：其所属 Relation 分支只有小幅上涨，Open-World Exploration 从 26.5 到 35.9，增加 9.4 分。但其他分支并未同步改善。

这说明在当前配方下，训练收益有明显方向性。可能涉及表征变化、优化干扰和数据分布差异。实验本身没有证明“基础技能天然互斥”，也没有定位具体是哪一层参数造成干扰。

### 6.3 联合训练：有协同，但不是每个能力都受益

三能力联合总分 26.1，比任意单能力配方都高；加入 Motion 后达到 27.3。这支持多类基础监督具有互补性。

直观上，规划物体如何移动往往同时需要位置、尺寸和跨视角对应。只改善其中一项，其他瓶颈还在；联合训练可能缓解多个瓶颈，也可能减轻偏向单一数据分布造成的退化。

但三能力联合模型的 Localization 仍只有 16.4，低于 baseline 的 24.2。加入 Motion 后，Motion 分支本身也没有简单地超过 baseline。训练集名字与最终能力变化不是一一对应关系。

因此论文给出的是“值得研究多能力组合”的证据。若要严格证明某种组合产生因果协同，还需要更完整的等预算组合消融、数据配比控制、重复训练和误差范围。

## 7. RL 实验：为什么要有 Auto-Think？

### 7.1 这里的 RL 在优化什么？

作者使用 Qwen2.5-VL-7B 和 GRPO，研究 Reinforcement Learning with Verifiable Rewards。训练奖励主要围绕离散选择题答案的正确性，测试则包含数值、语义和动作相关度量。

因此它是在训练多模态模型的回答策略，不能直接理解成机器人在物理环境里靠成功奖励练操作。

GRPO 的基本过程是：同一个问题采样一组回答，给各回答评分，再鼓励奖励相对更高的回答。组内优势可用下面的简化式帮助理解：

$$
\hat A_i=\frac{r_i-\bar r}{\operatorname{std}(r)+\epsilon}.
$$

这是通用机制示意，不包含完整的概率比率裁剪、KL 约束等实现细节。论文没有充分给出全部超参数和奖励系数，因此不能凭这一式子完整复现。

### 7.2 为什么“多思考”可能损害感知？

直接估计深度，需要可靠的视觉几何线索。长文本推理可能帮助利用已知尺度，也可能引入类别刻板印象和未经观察支持的假设。输出更长，本身不会增加输入图像的信息。

而规划需要保持多个中间状态、比较操作顺序和检查约束，显式推演更可能有帮助。

论文据此设计不同层级的奖励方式：对直接感知任务，减少对思考过程的鼓励并加入长度惩罚；对复杂推理与规划，保留对推演的鼓励。这就是 Auto-Think 的主要思路。

它发生在训练目标中。不能只把它理解成部署时给某些题打开 Thinking 开关，也不能认为模型里因此多出了两个独立的快慢网络。

这一机制仍有重要的复现问题：长度究竟统计什么、系数多大、推理相关奖励如何计算、哪些任务使用哪种奖励。论文的高层描述不足以唯一确定这些配置。

### 7.3 看增益时，要用正确的 baseline

| 配方 | 总分 | 相对同一 SFT 起点 |
| --- | ---: | ---: |
| SFT Baseline | 27.3 | — |
| L1 RL @think | 26.6 | −0.7 |
| L3 RL @think | 27.7 | +0.4 |
| L4 RL @think | 28.5 | +1.2 |
| Full RL @think | 30.1 | +2.8 |
| Full RL @auto-think | 30.8 | +3.5 |

这里按 Table 3 显示的一位小数原始分数重算差值。原表括号把最后两项写作 +2.9、+3.6，与显示值相减不一致；附件沿用了括号值。笔记不把这 0.1 分差异包装成额外增益。

最直接的 Auto-Think 对照是 **30.8 对 30.1，增加 0.7 分**。它不是在普通 Full RL 之外再提高 3.6 分。

同时比较各分支：

| 能力 | Full RL @think | Full RL @auto-think |
| --- | ---: | ---: |
| Geometry | 29.7 | 31.9 |
| Motion | 24.7 | 28.6 |
| Relation | 27.2 | 22.0 |
| Memory | 16.7 | 22.6 |
| Sequential Planning | 37.6 | 35.6 |
| Goal-driven Execution | 25.4 | 23.4 |
| Open-World Exploration | 41.7 | 44.1 |

Auto-Think 在多个分支改善，另一些分支下降。结果更支持“奖励与计算方式应匹配任务”，而不是“Auto-Think 让每项能力都变好”。

还应区分两个 SFT baseline：Table 2 的通用数据 baseline 是 25.0；Table 3 进入 RL 的多能力 SFT 起点是 27.3。把它们混成一个，会高估或误解 RL 的贡献。

## 8. 这棵“树”到底被证明到了什么程度？

可以把证据分成三层理解。

**分类层：** 作者把分散的空间任务组织进四层体系。这提供了讨论和测量的共同语言，是明确的贡献。

**实验层：** 不同模型的能力分数具有相关结构；定向 SFT 和 RL 会在其他能力上产生正负变化。这说明能力之间的训练迁移值得系统研究。

**机制层：** 高层智能究竟必须依赖哪些低层表征、迁移通过哪些网络结构发生、是否存在唯一学习顺序，论文还没有严格确定。

尤其是 benchmark 总分本身经过层级加权。它反映作者对能力重要性的设计选择，不是一个天然存在的统一空间智商。研究机器人时，如果定位是核心瓶颈，就应单独看定位指标，不能让其他题的高分抵消实际控制中的关键失败。

此外，数据来自已有 benchmark、专家伪标签和自动改写，仍需注意数据来源交叉、标注误差与题目模板。作者声明训练和测试场景及物体配置分离，这是一项重要控制，但不能替代对原始数据来源和通用预训练污染的完整审计。

## 9. 和 RynnBrain 1.1 放在一起看

[RynnBrain 1.1](RynnBrain-1.1.md) 关注的是：通过空间和操作监督获得更好的具身基座，再用动作训练检验其价值。

SpatialTree 则提供另一侧的问题：加入这些监督后，究竟改善了哪些能力，又损害了哪些能力？

二者可以形成一个实验思路：

```text
改变具身预训练的数据组合
    ↓
分别测定位、对应关系、空间记忆、规划等能力
    ↓
固定动作训练或 Agent 执行系统
    ↓
测真实任务成功率与具体失败原因
```

这一流程能把“空间能力上涨”和“机器人变好”连接起来。只做中间的问答评测，无法证明执行收益；只做最后的成功率，又很难解释哪种监督起作用。

例如，若增加跨视角对应训练后，目标重识别变好、遮挡后恢复任务也变好，而静态抓取基本不变，这会比单纯报告总分提升更能支持机制解释。这个例子是研究假设，不是 SpatialTree 已完成的实验。

## 10. 对 RUA / Dex-RUA，我会怎么借鉴？

### 用它整理失败类型

| 执行现象 | 值得检查的能力 | 还需排除的执行因素 |
| --- | --- | --- |
| 末端总是落在目标后面 | 深度、坐标系、定位 | 标定误差与动作映射 |
| 转动视角后换错目标 | 对应关系、空间记忆 | 目标检测漏检 |
| 能找到目标但顺序错误 | 任务状态理解、序列规划 | 工具接口限制 |
| 抓住后滑落 | 抓取与接触表征 | 摩擦、力、控制频率 |
| 失败后反复执行同一动作 | 状态更新、诊断与重规划 | 反馈是否可观察 |

这些是诊断方向，不是从一次失败就确定原因的标签。比如抓空可能来自视觉，也可能来自控制标定，需要执行证据区分。

### 把能力干预做成受控实验

固定模型架构、机器人任务、执行接口和训练预算，只改变深度、对应、姿态或接触监督，再同时记录能力题和闭环表现。这样才有机会知道哪些数据真正值得采集。

如果评测中额外给模型深度图、对应点或物体坐标，应单独标明它是额外信息条件。训练中学会提取几何，与测试时直接获得几何提示，是两种不同的能力来源。

### 动态分配推理预算值得研究，但需要另外验证

Auto-Think 的启发是让计算投入匹配任务。机器人可以在简单状态更新时快速响应，在遮挡、接触异常或任务失败时增加诊断与规划计算。

但空间层级只是一个粗分类。简单任务也可能因为观测模糊而需要主动观察，复杂任务也可能已形成稳定技能。真正的在线预算策略可能还要考虑不确定性、时延和失败风险。

因此后续实验应同时记录成功率、推理 token、端到端响应时间和动作中断次数。只看到回答更短，不能证明控制更好。

## 11. 读完最值得留下的判断

SpatialTree 提供了一种有用的研究方式：把空间能力拆开测，再通过训练干预观察它们如何组合和迁移。

它提醒我们，数据量、思考长度和总体分数都不足以单独说明进步。Distance 训练可能帮助行动题，却损害其他感知题；联合训练可以提高总分，却保留明显短板；Auto-Think 的整体收益也伴随分支间取舍。

对于具身研究，我会把它用于选择训练数据、设计能力消融和整理失败原因，并用真实闭环执行检验这些能力是否有用。最终需要回答的仍是：模型增加了哪些可靠的空间信息，这些信息是否改变了正确行动的概率。
