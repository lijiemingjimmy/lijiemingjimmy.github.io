Unified Training：把预训练、SFT 和适当的 RL 更新放进同一个训练器

通常训练一个语言模型，会先读通用文本，再读领域材料和指令示范，最后根据奖励学习。每次切换阶段，数据、损失和运行系统都可能一起改变。Unified Training 提出一个更便于联合研究的视角：统一模型拟合数据的规则，把主要设计问题转移到“现在该学哪些数据、各占多少、何时调整”。

关键连接来自 MaxRL：对于二元奖励，它可以被解释成拟合模型自己生成的成功答案分布。这样，通用文本、示范和筛选后的模型回答就能采用共同的加权负对数似然训练。

论文：Training Foundation Models with a Single Algorithm，Yuda Song、Alvin Zhang、Fahim Tajwar 等，CMU、Johns Hopkins 与 Aurora Innovation，arXiv:2610.40564，2026 年 10 月 29 日提交。

论文｜正文与附录｜项目页

1. “统一”发生在哪一层？

预训练、Midtraining 和 SFT 本来就大量使用最大似然估计。设提示为 xxx，回答为 yyy，模型为 πθ(y∣x)\pi_\theta(y\mid x)πθ​(y∣x)，训练数据分布为 qqq，则：

L(θ;q)=−E(x,y)∼qlog⁡πθ(y∣x). \mathcal L(\theta;q)=-\mathbb E_{(x,y)\sim q} \log\pi_\theta(y\mid x). L(θ;q)=−E(x,y)∼q​logπθ​(y∣x).

不同阶段主要改变目标数据：

来源 模型拟合什么 哪些 token 参与损失
Pretraining 通用文本 语料 token
Midtraining 筛选后的领域文本、推理材料等 语料 token
SFT 给定指令的示范回答 回答 token，提示掩码
本文的 RL 数据 生成策略中经过奖励筛选、加权的回答 回答 token，按奖励设权重

困难在于最后一行：RL 通常优化奖励，为什么也能写成拟合数据？论文通过成功条件分布建立这一联系。

统一的是学习目标的形式、样本表示和训练器。生成、奖励验证、数据采样与优化仍需设计；同一个损失函数并没有让所有训练配置自动变成最优。原文 §2–4

2. MaxRL 怎样变成“学习自己做对的答案”？

先考虑奖励 r(x,y)∈{0,1}r(x,y)\in\{0,1\}r(x,y)∈{0,1}。定义一道题的成功概率：

pθ(x)=∑yπθ(y∣x)r(x,y). p_\theta(x)=\sum_y\pi_\theta(y\mid x)r(x,y). pθ​(x)=y∑​πθ​(y∣x)r(x,y).

当 pθ(x)>0p_\theta(x)>0pθ​(x)>0 时，模型的成功条件分布为：

πθ+(y∣x)=πθ(y∣x)r(x,y)pθ(x). \pi_\theta^+(y\mid x) =\frac{\pi_\theta(y\mid x)r(x,y)}{p_\theta(x)}. πθ+​(y∣x)=pθ​(x)πθ​(y∣x)r(x,y)​.

直觉上，它保留模型生成的正确回答，并将概率重新归一化。它不是外部老师提供的唯一标准解，也不保证其中每条推理过程都可靠；“成功”依赖奖励验证器的定义。

MaxRL 最大化 Ex∼ρlog⁡pθ(x)\mathbb E_{x\sim\rho}\log p_\theta(x)Ex∼ρ​logpθ​(x)。对单个提示求导：

∇θlog⁡pθ(x)=1pθ(x)∑yr(x,y)∇θπθ(y∣x)=∑yπθ(y∣x)r(x,y)pθ(x)∇θlog⁡πθ(y∣x)=Ey∼πθ+(⋅∣x)∇θlog⁡πθ(y∣x). \begin{aligned} \nabla_\theta\log p_\theta(x) &=\frac{1}{p_\theta(x)}\sum_y r(x,y)\nabla_\theta\pi_\theta(y\mid x)\\ &=\sum_y\frac{\pi_\theta(y\mid x)r(x,y)}{p_\theta(x)} \nabla_\theta\log\pi_\theta(y\mid x)\\ &=\mathbb E_{y\sim\pi_\theta^+(\cdot\mid x)} \nabla_\theta\log\pi_\theta(y\mid x). \end{aligned} ∇θ​logpθ​(x)​=pθ​(x)1​y∑​r(x,y)∇θ​πθ​(y∣x)=y∑​pθ​(x)πθ​(y∣x)r(x,y)​∇θ​logπθ​(y∣x)=Ey∼πθ+​(⋅∣x)​∇θ​logπθ​(y∣x).​

于是，在第 ttt 次更新，可以构建一个固定目标：

Lt(θ)=−Ex∼ρ,y∼πθt+log⁡πθ(y∣x). \mathcal L_t(\theta)= -\mathbb E_{x\sim\rho,y\sim\pi_{\theta_t}^+} \log\pi_\theta(y\mid x). Lt​(θ)=−Ex∼ρ,y∼πθt​+​​logπθ​(y∣x).

在 θ=θt\theta=\theta_tθ=θt​ 处，其负梯度就是对应的 MaxRL 梯度。求导时必须把目标分布固定下来。 如果边求导边把目标内部的 θ\thetaθ 也一起微分，就不再是上述拟合步骤。固定数据重复更新多步，也不能逐步都宣称是精确的当前策略 MaxRL。原文 §3.1

3. REINFORCE 与 MaxRL 都学正确答案，区别在哪里？

普通期望奖励目标是：

JRF(θ)=Ex∼ρpθ(x). J_{\mathrm{RF}}(\theta)=\mathbb E_{x\sim\rho}p_\theta(x). JRF​(θ)=Ex∼ρ​pθ​(x).

其梯度可写为：

∇JRF=Ex∼ρ[pθ(x)Ey∼πθ+∇log⁡πθ(y∣x)]. \nabla J_{\mathrm{RF}} =\mathbb E_{x\sim\rho} \left[p_\theta(x) \mathbb E_{y\sim\pi_\theta^+} \nabla\log\pi_\theta(y\mid x)\right]. ∇JRF​=Ex∼ρ​[pθ​(x)Ey∼πθ+​​∇logπθ​(y∣x)].

与 MaxRL 相比，多了提示相关的权重 pθ(x)p_\theta(x)pθ​(x)。所以在二元奖励下，两者的条件回答目标相同，但提示的有效权重不同：

目标 对提示的有效加权
MaxRL 保留原提示分布 ρ(x)\rho(x)ρ(x)
REINFORCE 与 ρ(x)pθ(x)\rho(x)p_\theta(x)ρ(x)pθ​(x) 成正比

这说明未经归一化的 REINFORCE 更容易从本来就常做对的题得到更新。MaxRL 尝试减少这种成功率造成的权重差异，但它仍然需要先采到正确答案。

严格说，把有效提示权重归一化成概率分布，还会引入一个整体梯度比例；在混合其他数据源时，这个比例需要体现在来源权重或优化尺度里，不能随意忽略。

论文还讨论连续奖励下的 REINFORCE 与 TailRL。它们分别使用奖励加权目标，或不同奖励阈值以上的条件分布混合。这里的统一针对适当的目标构造，不意味着任意带 clipping、负优势或其他约束的 PPO／GRPO 实现都与非负加权交叉熵完全等价。原文表 2 与附录 F

4. 有限采样的实现：难题为什么仍可能学不到？

对每个提示采样 nnn 个回答，设正确回答数为 mmm，通过率估计为：

p^=m/n. \hat p=m/n. p^​=m/n.

当 m>0m>0m>0 时，每条正确回答的权重为 1/p^=n/m1/\hat p=n/m1/p^​=n/m，错误回答权重为零。对这组回答取平均后：

1n∑i=1nrip^∇log⁡πθ(yi∣x)=1m∑i:ri=1∇log⁡πθ(yi∣x). \frac1n\sum_{i=1}^{n}\frac{r_i}{\hat p} \nabla\log\pi_\theta(y_i\mid x) =\frac1m\sum_{i:r_i=1}\nabla\log\pi_\theta(y_i\mid x). n1​i=1∑n​p^​ri​​∇logπθ​(yi​∣x)=m1​i:ri​=1∑​∇logπθ​(yi​∣x).

例如采 8 次、正确 2 次，每条正确回答权重为 4；组内平均后，就是两条正确回答梯度的平均。若 8 次全错，应直接令本组更新为零，不能计算 1/01/01/0。原文 §4.2

有限采样还引入一个重要权重：

qn(x)=1−(1−pν(x))n. q_n(x)=1-(1-p_\nu(x))^n. qn​(x)=1−(1−pν​(x))n.

它是一组采样至少成功一次的概率。对于生成器 ν\nuν，这一提示级平均估计的期望，等于成功条件分布的梯度乘 qn(x)q_n(x)qn​(x)。下面是自行计算的示例：

单次成功率 采 1 次 采 8 次 采 64 次
1% 1.0% 7.7% 47.4%
10% 10.0% 57.0% 99.9%

所以有限预算下，极难题仍会被明显降低权重。增加采样次数能帮助发现稀有成功，但也增加生成和验证成本。若生成策略根本没有成功支持，单靠筛选成功样本无法产生学习信号，需要示范、更合适的课程或其他探索机制。

这个公式描述的是提示组的梯度平均。实际训练还有 token 长度、batch 归一化和混合比例，不能把它直接当成最终 minibatch 梯度的全部描述。

5. 单一数据分布如何包含所有阶段？

让来源 sss 在时刻 ttt 的联合分布为 qs,t(x,y)q_{s,t}(x,y)qs,t​(x,y)，混合比例为 λs,t\lambda_{s,t}λs,t​，则：

qt(x,y)=∑sλs,tqs,t(x,y),λs,t≥0,∑sλs,t=1. q_t(x,y)=\sum_s\lambda_{s,t}q_{s,t}(x,y), \qquad \lambda_{s,t}\ge0,\quad\sum_s\lambda_{s,t}=1. qt​(x,y)=s∑​λs,t​qs,t​(x,y),λs,t​≥0,s∑​λs,t​=1.

训练目标仍然是：

Lt(θ)=−E(x,y)∼qtlog⁡πθ(y∣x). \mathcal L_t(\theta)=-\mathbb E_{(x,y)\sim q_t} \log\pi_\theta(y\mid x). Lt​(θ)=−E(x,y)∼qt​​logπθ​(y∣x).

分阶段训练可以看成一种极端调度：某段时间主要用通用语料，下一段切换到领域数据，随后使用生成数据。统一训练允许它们重叠，并让比例随时间变化。

例如，一段训练末期逐渐加入推理材料；进入数学 RL 后，仍保留少量旧语料，以持续练习更广泛的能力。这与“把所有数据永久等比例混在一起”不同，调度本身就是要研究的对象。

统一视角也不取消优化器的作用。学习率、batch、调度和模型状态会影响相同数据带来的更新；来源比例只是重要变量之一。原文 §3.2 与讨论

6. Token 权重和归一化：实现中最容易理解错的地方

训练器读取 token 序列 zzz 与非负权重 www，使用：

L^(θ;B)=−1TB∑(z,w)∈B∑ℓwℓlog⁡πθ(zℓ∣z<ℓ). \widehat{\mathcal L}(\theta;\mathcal B)= -\frac1{T_{\mathcal B}} \sum_{(z,w)\in\mathcal B}\sum_\ell w_\ell\log\pi_\theta(z_\ell\mid z_{<\ell}). L(θ;B)=−TB​1​(z,w)∈B∑​ℓ∑​wℓ​logπθ​(zℓ​∣z<ℓ​).

分母 TBT_{\mathcal B}TB​ 是 batch 中所有非提示 token 的数量，不是权重之和，也不只是正确回答的 token 数。预训练和领域语料权重为 1；SFT 提示权重为 0、回答为 1；RL 提示为 0，回答使用上一节的权重。原文式（2）

若某来源目标 token 比例为 fsf_sfs​，每个样本平均有 TsT_sTs​ 个可计数 token，样本采样率应与 fs/Tsf_s/T_sfs​/Ts​ 成正比。长回答和短文本各占一半样本，并不意味着各占一半 token。

但 token 占比也不等于梯度贡献占比。RL 的响应权重、长度分布，以及每个 token 的实际梯度大小都会影响贡献。复现时应同时记录样本数、token 数、权重和及实际来源分布。

可以用下面的概念代码理解训练器，具体实现还要处理 packing、分布式归一化等细节：

# 示意，非论文仓库的可运行复现
batch = sample_mixed_buffer(schedule)
logp = model_token_logprobs(batch.tokens)
loss = -(batch.weights * logp).sum()
loss = loss / batch.non_prompt_token_count
loss.backward()
optimizer.step()

与分别算 Lstatic+γLRLL_{\mathrm{static}}+\gamma L_{\mathrm{RL}}Lstatic​+γLRL​ 相比，这里通过共同分母和数据组成控制相对尺度。两者在恰当设置系数时可能相关，关键是要对齐实际归一化，而不是只比较公式里有没有加号。

7. 异步生成为什么可行，又改变了什么？

近期模型副本 → 生成多个回答 → 奖励检查与赋权
                                  ↓
静态语料／示范 ─────────────→ 共享数据缓冲区
                                  ↓
                         统一似然训练器
                                  ↓
                       定期发布新模型权重
                                  ↓
                         生成器加载并继续

生成策略 ν\nuν 可以是较旧版本，也可以是另一个固定生成器。训练器仍然能拟合它的成功条件分布 ν+\nu^+ν+。但当 ν≠πθt\nu\ne\pi_{\theta_t}ν=πθt​​ 时，这通常不再是当前策略的 MaxRL 梯度。原文 §3.2

因此，数学上存在合法的似然目标，与策略滞后对效果没有影响，是两回事。旧数据的成功模式可能已经不能代表当前模型最需要学习的内容；缓冲区的年龄、权重同步频率和重复使用次数都会改变实际目标。

这个系统简化了训练接口，但奖励验证器和数据生成仍然不可或缺。它也没有自动解决错误奖励、成功样本过窄或长期重复导致的多样性下降。

附录 D.6 还揭示了比较时需要拆开的实现差异：Unified 使用缓冲区旧策略数据与 r/p^r/\hat pr/p^​ 权重；staged 基线使用更新前新生成的数据，并采用 (r−p^)/p^(r-\hat p)/\hat p(r−p^​)/p^​ 权重。理想 on-policy 总体期望下，减去与回答无关的 baseline 不改变策略梯度；但有限样本估计和旧策略数据下，不能直接把两条实现当成完全等价。

实验每 4 次更新发布权重，但快照里的生成批次仍可能落后 12–44 次更新，而且没有记录训练器实际消费样本的精确版本分布。论文报告的约 7.8 倍更新吞吐差异也涉及 24 对 16 张 GPU 以及响应复用，不能解释成同硬件、同新鲜 rollout 预算下的纯算法加速。附录 D.6

8. 受控实验：统一训练并非每个预算都赢

第一组实验从头训练 124M 模型，固定 20B-token 预训练语料与 510M-token Midtraining 语料。领域材料提供推理操作示范，RL 引入这些操作的新组合。

设置 训练与测试关系
Base 谜题规模处于 Midtraining 覆盖范围
Extended RL 引入更大谜题，测试同规模的留出问题
Extended generalization 用 Extended 模型测试比两阶段所见都更大的谜题

Base 使用 6000 次 RL 更新，Extended 使用 12000 次；结果平均两个训练种子，报告 pass@1 和 pass@16。最佳统一配置在最终表现上超过分阶段配置，也更能利用重复使用的领域语料。原文 §5.1

但固定 RL 更新数还没有对齐总算力，因为统一训练额外处理了静态数据。等总预算比较得到更细的结论：

  • Base 和 Extended 的中等预算下，分阶段训练在准确率上可以更优；更大预算时统一训练优势更明显。
  • Base 和 Extended 的覆盖率计算效率上，分阶段训练仍有优势。
  • 更大谜题的泛化评估中，统一训练在几乎所有测试预算下取得较好的准确率与覆盖率。

这里的最佳前沿来自已测试配置和 checkpoint 的选择，属于观察到的实验边界，尚不是能预测任意规模的 scaling law。原文 §5.1.2

9. 真实语料实验：保留能力要付出哪些代价？

第二组使用 0.76B 模型，在 Math12K 上进行数学 RL，并混入一个 240M-token 的异构语料库，包含网页、数学、代码和推理轨迹。比例从 0% 扫到 5%。

这里 Math 指 MATH-500 与 GSM8K 的均值，Coding 指 HumanEval+ 与 MBPP+ 的均值；数学训练后的覆盖率使用 pass@32，不能与前一组 pass@16 直接混比。

pass@k 衡量采样 k 次至少得到一个正确答案的概率，不意味着模型能自行识别并选出那个答案。这组异构数据实验固定优化更新次数，没有严格匹配总计算量。

观察结果可以概括为：

指标 增加静态数据混合后的表现
Math pass@1 大体相近，高比例时略有下降
Math 覆盖率 最大混合比例表现最好，趋势并非严格单调
留出语料 loss 非零混合明显改善能力保留
SciQ 总体随混合增加而改善
Coding pass@1 通常下降
Coding 覆盖率 相对分阶段等对照仍可保持优势

所以“保留更广能力”不能理解成每个 benchmark 同时提高。甚至语料里有代码，也不保证编程 pass@1 更好：来源质量、风格、梯度干扰和调度都会影响结果。原文 §5.2 与附录 D

作者还比较平均配置比例同为 0.5% 的固定混合、线性衰减、线性增长、半程结束混合。半程结束可以提高最终 Coding 和 SciQ 表现，但牺牲一部分留出语料 loss 的改善。实际 token 比例还会随回答长度变化，因此配置平均比例和实现后的比例应分别记录。

附录表 17 给出一组具体对照，前三列为百分数：

调度 Math pass@1 Coding pass@1 Coding pass@32 留出语料 Δloss
固定 0.5% 24.27 16.51 46.38 −0.0871

10. 最有启发的结果：当前分数低，后面反而学得更好

数学 RL 结束后，所有模型采用相同 Coding RL 流程，不再混入 Midtraining 数据。统一训练模型虽然初始 Coding 准确率较低，后续训练后却在两个编程基准的准确率上超过分阶段模型；5% 混合配置在该组报告的四项指标上最好。

这组持续学习评估报告 4000 次 Coding RL 更新后的 pass@1 和 pass@16。它与数学训练后使用 pass@32 的覆盖率图属于不同协议。原文 §5.2.3 与附录 D.7

我认为这是比“某个终点分数更高”更重要的发现：一个中间模型的价值，还包括它是否容易继续学习。 只按 Midtraining 结束时的分数选模型，可能错过更适合后续 RL 的初始化。

不过，它目前支持的是所测任务顺序下的结果。更长的任务序列、顺序变化，以及旧能力是否在后续持续保留，仍需要验证。

11. 它与 SFT、拒绝采样和 KL 正则有什么关系？

“生成若干答案、筛选正确答案、再训练”与成功数据自训练有直接联系。本文更明确地给出目标分布、提示权重和有限采样修正，并把它们连接到全训练过程的数据混合。

如果把所有成功回答直接堆在一起做 SFT，容易做对的题通常留下更多样本。MaxRL 的组内归一化试图改变这种提示加权。即使最后都调用交叉熵训练器，也不能忽略数据生成与赋权的差异。

KL 正则和静态数据重放也不完全相同：前者约束模型在指定输入分布上接近参考策略；后者直接提供需要继续学习的文本或示范。论文测试的 KL 系数不能同时复现统一训练的数学表现和保留收益，但这是一组实验结论，不是证明所有 KL 设计都无效。原文附录 E

同样，错误回答零权重不意味着训练完全没有改变它们的概率。提高成功回答概率，会通过概率归一化影响其他回答；只是这里没有逐条指定错误回答的负向 token 梯度。

12. 和 Scaling Law、WAM、机器人学习怎样接起来？

上一篇 视频基模 Scaling Law 笔记 讨论参数、数据和计算怎么分配。Unified Training 进一步提醒我们：即使总数据量相同，使用顺序和模型当时的状态也会改变结果。

未来可以研究整个数据调度轨迹 {λs,t}\{\lambda_{s,t}\}{λs,t​}，在固定总预算下优化最终能力、旧能力保留和后续适配效率。生成数据成本应包含 rollout 和验证，不能只统计反向传播 token。本文尚未给出一套通用、可外推的全生命周期 scaling law。

对机器人，可以借鉴“示范与在线成功经验共享训练系统”的思路，但要重新处理三个问题：

  1. 成功很稀疏。 某个状态下始终无法完成任务时，成功筛选没有信号，示范、课程与探索更重要。
  2. 环境参与了轨迹分布。 机器人不仅生成文本，还改变环境；似然要对应策略动作，不能把环境状态的概率当成可训练的策略项。
  3. 动作模型的损失不同。 Diffusion／Flow Matching 常用去噪或速度回归损失，不能直接声称与本文 token 加权交叉熵的等价推导一致。

一个可做的研究是固定机器人数据、控制器和任务集，对比分阶段 BC→RL、RL 中混合示范，以及随成功率调整的示范调度。统一计算预算，分别记录当前任务成功率、旧任务保留和新任务的学习速度。这是由本文引出的实验建议，不是论文已经完成的机器人验证。

13. 我会怎样判断这项工作的价值？

我会保留三个判断。

第一，数学联系是具体的：在明确的奖励和目标条件下，RL 更新能写成对成功条件分布的似然拟合。这让静态数据与生成数据共享训练器有了依据。

第二，数据来源的价值依赖时机。重复一份语料可能帮助后续学习，也可能损害当前专门任务。需要把比例、调度和归一化作为研究对象，而不是默认“多混一点就能避免遗忘”。

第三，实验仍主要在 124M 与 0.76B 模型、有限任务序列上展开。它展示了值得研究的训练组织方式，也给出了精确的取舍；还没有证明所有模型规模、RL 算法和模态都应采用同一配方。

这篇论文真正推进的问题是：怎样选择一条训练轨迹，让模型不仅当前做得好，还能保留旧能力，并且更容易学会下一件事。
