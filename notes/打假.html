打假：别把 Benchmark 涨分直接写成推理能力进步

主题：LLM 推理与强化学习研究中的评测、机制解释和能力主张核查
材料范围：A Sober Look、Spurious Rewards，以及 Incorrect Baseline Evaluations 评论与作者讨论
整理日期：2026-10-20
核查方式：整理用户提供的三份解读，核对原文、图表、版本记录与原始讨论；没有重新训练或复跑全部模型。

三份材料共同提出一个研究问题：分数提高了，现有实验究竟排除了哪些更简单的解释？

需要被检查的解释包括：基线没调好、格式更匹配评分器、推理预算改变、采样偶然性，以及模型更常调用已有的成功策略。不同解释可能同时成立，训练也可能产生真实收益。

“报告不充分”“归因过强”“无法复现”和“主观造假”需要不同证据。本文讨论可复核的实验问题，不依据这些材料判断作者的主观动机。

1. 三份材料分别提供了什么证据

材料 实验或论证方式 主要发现 证据边界
A Sober Look 量化评测因素、统一流程复测、逐题配对统计 部分报告分数下降，部分 RL 收益较弱，也有可靠改善的模型 调查的是特定公开模型；不构成所有 SFT 与 RL 的等预算因果比较
Spurious Rewards 更换奖励、跨模型实验、行为干预、clipping 消融 部分 Qwen 模型用随机或错误标签奖励也能涨分 现象依赖模型与设置；机制解释仍有未闭合部分
Incorrect Baseline Evaluations 对照多篇论文与外部参考基线 部分 Pre-RL 分数明显低于其他评测 缺少全部训练前后模型的同协议复测，不能直接给出每种方法的真实训练效应

三种证据针对不同问题：分数能否复现、奖励信息是否必要，以及原有能力归因是否充分。不能把它们拼成“所有 RL 提升都已被推翻”。

分篇笔记：A Sober Look、Spurious Rewards、Baseline 评论。

2. 先明确到底在比较什么

把观测到的准确率记为：

A(θ,e;D) A(\theta,e;D) A(θ,e;D)

其中 θ\thetaθ 为模型参数，DDD 为测试题集合，eee 包含 prompt、模板、解码策略、长度预算、parser、grader、软件和硬件等评测条件。

跨论文常见的差值是：

Δreported=A(θRL,e1;D)−A(θ0,e0;D) \Delta_{\mathrm{reported}} =A(\theta_{\mathrm{RL}},e_1;D) -A(\theta_0,e_0;D) Δreported​=A(θRL​,e1​;D)−A(θ0​,e0​;D)

当 e1≠e0e_1\ne e_0e1​=e0​ 时，参数更新与配置变化混在一起。即使配置相同，涨分也仍可能来自格式、策略选择和求解质量等不同方面。

2.1 固定协议下，训练是否有效

Δtrain(e)=A(θRL,e;D)−A(θ0,e;D) \Delta_{\mathrm{train}}(e) =A(\theta_{\mathrm{RL}},e;D)-A(\theta_0,e;D) Δtrain​(e)=A(θRL​,e;D)−A(θ0​,e;D)

它回答：在给定使用条件下，这次权重更新是否改善表现？它不要求模型必须创造全新的解题策略。

2.2 给基线同等调优机会后，是否仍有额外价值

对每个模型，在独立验证集上以可比预算选出配置：

e^m=Select⁡(θm,Dval,B) \widehat e_m=\operatorname{Select}(\theta_m,D_{\mathrm{val}},B) em​=Select(θm​,Dval​,B)

然后只在保留测试集上比较：

Δtuned=A(θRL,e^RL;Dtest)−A(θ0,e^0;Dtest) \Delta_{\mathrm{tuned}} =A(\theta_{\mathrm{RL}},\widehat e_{\mathrm{RL}};D_{\mathrm{test}}) -A(\theta_0,\widehat e_0;D_{\mathrm{test}}) Δtuned​=A(θRL​,eRL​;Dtest​)−A(θ0​,e0​;Dtest​)

这里 BBB 为配置搜索预算。这比直接在测试集对两个模型各取最高分更可信，也区分了“权重更新的作用”与“最终系统选择”。

两种比较都需要报告实际 token、延迟等成本。最大长度相同，实际推理开销仍可能不同。

3. 三组有分量的事实，分别能说明什么

3.1 统一复测确实会改变对部分方法的判断

A Sober Look 中，Open-RS3 的 AIME'24 原报告为 46.7%，统一重测为 29.7%；R1-Distill-1.5B 基线为 28.7%。由此，原先很醒目的优势在这一复测流程中没有得到支持。

但该文也报告 DeepScaleR、FastCuRL 等在部分任务上仍保留统计显著收益，v2 中 Nemotron-RR 的改善更稳健。不能只摘录失败案例，再写成“RL 完全没用”。来源：Figure 1 与 Table 3

还要区分两个差值：

  • 46.7−29.7=17.046.7-29.7=17.046.7−29.7=17.0 pp 是原报告与复测值的差异。
  • 29.7−28.7=1.029.7-28.7=1.029.7−28.7=1.0 pp 才是这一流程下模型相对基线的均值差。

前者不能直接称为“RL 效果减少了 17 个百分点”，后者也不能脱离逐题数据和不确定性单独裁定效果。

3.2 无信息奖励也能涨分，但现象有模型条件

Spurious Rewards v2 的 Figure 1 给出 Qwen2.5-Math-7B 在 MATH-500 上的结果：

条件 准确率 相对初始值增益
未训练 49.4% —
真实奖励 78.5% +29.1 pp
特定错误标签奖励 73.5% +24.1 pp
随机奖励 70.8% +21.4 pp

Post-RL 值由初始值与图中增益相加得到，终值含论文所说明的训练步平滑。随机奖励独立于答案正确性，所以这些结果反驳了“看到涨分，就足以说明正确性监督带来了全部增益”的推断。来源：Figure 1 与 Appendix A.6

同时，真实奖励表现更好，同类随机奖励在 Llama、OLMo 等模型上未呈现相同收益。训练仍使用数学问题和预训练模型，因此“奖励无正确性信息”也不能写成“完全没有先验与任务信息”。

2025 年 Baseline 评论引用以下早期数字：

工作 起点模型 论文 Pre-RL 论文 Post-RL 外部参考 Pre-RL

这些数值足以提示原基线未被充分调用的可能性，但来源协议不同。“Actual Pre-RL”这个原表标签也不代表存在脱离评测条件的唯一准确率。来源：评论汇总表

例如：

70.1−64.6=5.5 pp 70.1-64.6=5.5\text{ pp} 70.1−64.6=5.5 pp

算术成立，但 5.5 pp 不是已经验证的 RL 真实净增益。将训练后模型放入新的评测配置，其分数也可能变化。

4. 常见说法逐条判定

说法 判定 更准确的表述或所需证据
RL 后分数提高，说明新增了推理能力 推断过强 已证明某配置下表现改善；新增能力还需迁移、预算控制和策略分析
随机奖励有效，所以奖励正确性不重要 推断过强 部分增益可在无正确性奖励下出现；真实奖励仍有额外收益
格式奖励能涨分，说明所有提升都是 parser 假象 缺少证据 格式可能解释部分收益，需重评分、输出审计和行为干预
外部 Base 分数高于论文 Post-RL，说明训练使模型退化 不能据此推出 需要两者在同一协议下的配对比较
多跑 30 个 seed，就相当于拥有 30 倍测试题 错误 重复生成降低解码噪声，不增加不同问题的数量
两个标准差区间重叠，说明没有显著差异 错误 应检验同题配对差值，标准差区间不等于差值置信区间
输出越长越容易错，所以删短推理能提高能力 因果推断不足 题目难度可能同时影响长度和正确性，需要长度干预
大 k 的 Pass@k 变差，证明了内部能力消失 推断过强 支持成功覆盖变化，不能唯一确定内部机制
这批公开 SFT 模型表现好，说明 SFT 普遍优于 RL 超出比较范围 需要对齐基座、数据、预算和目标的受控实验
未达显著，说明方法无效 错误 可能是效应小、样本不足或方差大；证明等效需单独设计

机制研究可以提出强假说，但每个假说应当对应能够排除竞争解释的实验。

5. 三份解读自身也需要核查

5.1 不能混用 Qwen2.5-7B 与 Qwen2.5-Math-7B

41.6% 对应普通 Qwen2.5-7B，49.4% 对应 Qwen2.5-Math-7B。它们在 Spurious Rewards v2 Figure 1 中同时出现，是两个模型，不能把初始值和终值交叉相减。

64.6% 和 64.3% 也应保留各自出处、模型及评测口径，不能看作只差四舍五入的同一结果。

5.2 不能把早期评论当成对后续修订版的完整反驳

LessWrong 链接帖发布于 2025-05-29；Spurious Rewards 的 arXiv v1 为 2025-06-12，v2 为 2026-02-25。评论原文引用了 GitHub 上的公开材料，因此不应把这个时间顺序当作文章不存在的证据。

同样，早期引用的 70.1% 不能不加版本说明就替代 v2 中的结果，也不能说该评论已经检验了 v2 新增的全部分析。来源：评论原文、LessWrong 日期、arXiv 版本记录

5.3 Spurious Rewards v2 中确实有一处数字不一致

v2 引言写 Qwen2.5-Math-7B 含代码回答准确率为 60.9%，无代码为 28.0%；Table 1 将无代码准确率写为 35.0%，并报告代码占比 65.0%。

假设这些数字来自同一批被划分为两类的输出，按 Table 1 加权：

0.65×60.9%+0.35×35.0%=51.835% 0.65\times60.9\%+0.35\times35.0\%=51.835\% 0.65×60.9%+0.35×35.0%=51.835%

与 49.4% 初始准确率不符；改用引言中的 28.0% 得到：

0.65×60.9%+0.35×28.0%=49.385%≈49.4% 0.65\times60.9\%+0.35\times28.0\%=49.385\%\approx49.4\% 0.65×60.9%+0.35×28.0%=49.385%≈49.4%

**可以确认文字与表格有冲突；不能据此确认冲突的原因。**可能是笔误，也可能是未解释的统计口径差异。需要原始逐样本输出才能进一步判断，本文不将 35.0% 静默改为 28.0%。来源：v2 引言与 Table 1

5.4 “所有收益都是格式”也受到原文数据约束

Spurious Rewards Appendix I 的 Sober prompt 可解析率为 93.1%、准确率为 61.6%；Lorem Ipsum prompt 可解析率为 84.1%、准确率为 68.8%。最高解析率并不对应最高正确率。

这不足以排除全部 parser 问题，但已经说明仅凭解析率无法解释这些配置间的所有准确率差异。来源：Table 5

5.5 随机奖励梯度公式要写清条件

理想 policy gradient 在独立随机奖励下期望为零，与 GRPO 的 clipping 偏置可以同时成立：两者讨论的优化目标与条件不同。

在固定当前策略的局部推导中，ρ=1\rho=1ρ=1 时 clipping 不触发，偏置也为零；有限样本移动和后续重复更新才可能使 ratio 越界。还需注意：

∇θρ=ρ∇θlog⁡πθ \nabla_\theta\rho=\rho\nabla_\theta\log\pi_\theta ∇θ​ρ=ρ∇θ​logπθ​

将 ∇ρ\nabla\rho∇ρ 改写成 ∇log⁡π\nabla\log\pi∇logπ 时不能无条件遗漏 ρ\rhoρ。高概率 token 的边界例子也不能替代完整神经网络训练动态的证明。

6. 一项可信的复核至少怎样做

以下是基于三份材料归纳的复核方案，不是声称三篇作者已经共同执行了全部步骤。

第一步：锁定模型、数据和主张

记录模型完整名称、revision、参数规模、Base/Instruct/Distill 身份、论文版本和 benchmark 切分。先明确要核查的是准确率、效率、泛化、奖励机制，还是新能力。

如果训练前后起点模型本身不同，优先解决身份问题，再讨论百分点。

第二步：建立无需训练的强基线

保留默认配置，同时在验证集上，以相同搜索预算测试合理的 prompt、chat template、temperature、top-p 和输出预算。检查是否允许 few-shot，明确它与 zero-shot 对照的成本差异。

不能故意给基线使用不适合的配置，也不能用无限搜索的基线对比未经调参的方法。

第三步：同时重测训练前后模型

对每个候选协议，比较：

A(θ0,e),A(θRL,e) A(\theta_0,e),\qquad A(\theta_{\mathrm{RL}},e) A(θ0​,e),A(θRL​,e)

保留逐题答案、提取结果、正确性标签、token 数、截断状态和生成配置。Parser 改动需要同时重评分两类模型的输出，抽样检查误判，并避免根据模型身份调整标准。

第四步：把统计单位说清楚

对相同题目做 paired bootstrap 等配对分析；单次二值结果可考虑 McNemar test。多次生成时，需要保留“题目—生成”的层级，避免把高度相关的重复样本当作新增独立题目。

还应区分评测随机种子与训练随机种子。多次评测同一个 checkpoint 主要测量解码波动，不能证明算法跨训练运行稳定。

报告效应量和差值置信区间，明确多重比较处理。Greedy decoding 下反复换 seed，也不自动提供独立的解码采样证据。

第五步：按主张选择对照

待验证主张 有辨别力的对照
新奖励里的正确性信息有效 随机奖励、格式奖励、真实奖励，以及跨 backbone 对照
训练带来超出配置调优的收益 不更新权重的 prompt/decoding 调优
出现新的成功策略 训练前充分采样、轨迹分析、策略诱导与抑制干预
具有泛化收益 未用于调参的新任务、变体和分布变化
成本更低 相近准确率下的实际 token、延迟、训练与搜索成本

有限次采样中没观察到某策略，不能证明训练前模型的成功概率严格为零；“新能力”需要可操作的定义和更强证据。

7. 对具身 Agent / VLA，应该核查哪些类似问题

具身成功率可概念性地写成：

Sobs=f(π,初始状态,任务分布,环境,控制接口,执行预算,成功判定) S_{\mathrm{obs}}=f(\pi,\text{初始状态},\text{任务分布}, \text{环境},\text{控制接口},\text{执行预算},\text{成功判定}) Sobs​=f(π,初始状态,任务分布,环境,控制接口,执行预算,成功判定)

这个表达用于组织实验因素，不是已识别的因果分解。LLM 数学结果也没有证明随机奖励适用于机器人。

LLM 评测中的问题 具身评测中的对应检查
Prompt 和 chat template 任务指令、观测组织、相机与历史输入
Temperature 和随机采样 策略采样、环境 seed、物理扰动
输出长度 动作步数、episode 时长、重试次数
Parser / grader success checker、接触和姿态阈值、终止逻辑
推理后端与数值差异 仿真版本、求解器、控制频率、延迟与动作执行
格式改善 动作合法率、工具调用格式和控制接口匹配
既有策略重加权 更常选择已有的 grasp、approach 或 recovery 模式

有实际研究价值的复核可以按以下顺序展开：

  1. 固定任务版本、控制接口、执行预算和 success checker，对照相同 initial states。
  2. 同时记录成功率、完成时间、动作数、碰撞和人工干预。
  3. 主动制造可恢复失败，在可比的恢复机会中比较 recovery rate。
  4. 在新布局、新对象和扰动下检查结论是否保留。
  5. 如果排行榜改变，逐因素干预定位原因，避免止步于重新排序。

例如，某方法训练后 Success Rate 提高，但允许的重试次数也更多，需要先比较相同重试预算下的表现。若主张恢复能力增强，则应比较匹配的失败起点和恢复机会，而不只统计自然 rollout 中成功恢复的次数。

8. 怎样写出与证据强度匹配的研究结论

已有证据 合理的结论
一个 benchmark、一个协议下准确率提高 方法在该设置中改善了表现
相同条件、多种合理配置下都改善 训练收益对这些评测选择较稳健
超过无训练调优和奖励对照 收益难以完全由这些替代解释说明
在新分布和匹配成本下仍有收益 泛化或效率主张得到额外支持
有主动策略干预及逐样本证据 某种机制解释得到更强支持，仍需说明未排除的机制

对这组三份材料，最稳妥的判断是：部分早期推理进展被评测差异与基线选择放大；部分分数提升可以由既有行为的调用变化产生；也存在统一复测后仍保留的真实收益。后续研究需要把这些成分分开测量，并公开足够的逐样本证据。
